# Предметная модель панелей и локальных черновиков

**Статус:** нормативный контракт дизайна по O-025 (уточнение владельца 24.10.2026); переносимый формат решён O-026 (24.10.2026): `project/v2` с одним корнем `kind: dashboard|page`; реализация — P0-08. Этот документ не меняет существующие JSON Schema и Rust-модели сам по себе.

## 1. Серверные сущности Zabbix

ZDashstitch следует иерархии Zabbix 7.4:

```text
Dashboard
└── Page
    └── Widget
```

- `Dashboard` — глобальная панель Zabbix, серверная identity `dashboardid`.
- `Page` — страница внутри панели, серверная identity `dashboard_pageid`/`pageid` в зависимости от API DTO.
- `Widget` — виджет внутри страницы, серверная identity `widgetid` и внутренние `reference`.

В русском интерфейсе используются официальные термины локализации Zabbix 7.4: **панель → страница → виджет**, «узел сети», «элемент данных», «группа узлов сети», «только чтение» / «чтение-запись». Области самого интерфейса «панелью» не называются: «боковая колонка», «инспектор», «область». Глоссарий — `docs/design/P1-00F-message-inventory.md`.

## 2. Локальные сущности

### 2.1 Снимок и рабочая копия

`DashboardSnapshot`/`PageSnapshot` — неизменяемое чтение серверного объекта с provenance, server identity, version и fingerprint. `Workcopy` — Base snapshot + типизированные локальные операции + производный Local (O-018). В интерфейсе рабочая копия показывается как черновик панели или страницы с происхождением «Копия с сервера»; внутренне она остаётся отдельным видом объекта (Base + операции) и не становится переносимым черновиком без явного преобразования (P1-07I/P4-08).

### 2.2 Локальный черновик

Локальный черновик — переносимый объект вида `dashboard|page`, не серверная сущность Zabbix. В инженерных документах, ADR и задачах до решения O-026 он называется `Dashboard project` / `Page project` (typed project); это внутреннее имя. Слово «проект» в интерфейсе не используется: черновик называется своей сущностью — «Панель» или «Страница» — с происхождением «Локальная» (создан в ZDashstitch или импортирован из файла).

| Вид | Корень | Содержимое | Типичные результаты |
|---|---|---|---|
| `dashboard` | одна логическая панель | одна или несколько страниц, виджеты | «Создать панель», «Сохранить копию», основа Clone после явного преобразования |
| `page` | одна логическая страница | виджеты | «Добавить страницу в панель» либо страница в составе новой панели |

Набор выбранных виджетов является областью действия «Добавить виджеты на страницу», а не третьим видом черновика до отдельного решения.

Источник и назначение всегда независимы. Черновик страницы может происходить из страницы A панели X и публиковаться как новая страница B в панели Y. Имя, ID или fingerprint источника не определяют цель автоматически.

### 2.3 Страница как единица работы (O-027)

Страница работает отдельно от своей панели. Сценарии MVP:

1. «Взять страницу» — одна страница с панели на сервере, из файла или из библиотеки становится черновиком страницы.
2. «Добавить страницу в панель» — в существующую панель на сервере или в локальный черновик панели.
3. «Собрать панель из страниц» — новый черновик панели из страниц любых источников; затем «Создать панель».
4. «Экспорт и импорт страницы» — файл одной страницы (`project/v2`, `kind: page`, O-026); импорт нескольких файлов сразу.

При склейке значения `reference` должны быть уникальны в пределах панели; сервер этого не проверяет, поэтому совпадения переписывает ZDashstitch вместе со всеми потребителями. Узлы сети разрешаются по каждой странице. Страницы панелей шаблонов в MVP не принимаются.

### 2.4 Библиотека и пакет

Библиотека хранит снимки, страницы из файлов, каталоги метрик, профили оформления и заготовки виджетов как разные типы объектов. Локальные черновики живут в разделе «Локальные черновики», а не в библиотеке; ни один объект не называется «проектом».

DATA-ONLY ZIP — контейнер передачи. Контейнер не становится предметной сущностью UI и не доказывает обезличенность.

## 3. Операции

| Intent | Подпись в UI | Source | Target | Что не происходит |
|---|---|---|---|---|
| `CreateDashboard` | «Создать панель» | черновик панели (в том числе собранный из страниц) либо подтверждённая рабочая копия панели | новое имя в подключении | не ищет похожую панель и не перезаписывает существующую |
| `AppendPage` | «Добавить страницу в панель» | черновик страницы или выбранная страница из рабочей копии другой панели | явно выбранная панель | не объединяет страницы по имени |
| `AppendWidgets` | «Добавить виджеты на страницу» | явно выбранные виджеты | явно выбранная страница | не двигает существующие виджеты автоматически |
| `CloneDashboard` | «Клонировать панель» | рабочая копия или снимок панели | новая приватная панель в том же подключении | не превращает Clone в переносимый черновик автоматически |
| `ReplaceHost` | «Заменить узел сети» | рабочая копия панели или страницы с указанной областью | та же либо явно выбранная панель | не изменяет объекты вне области |

Внутренние имена intent показываются только в технических сведениях.

## 4. UI-контекст

Каждый экран редактора, предпросмотра и публикации показывает:

1. тип объекта («Панель»/«Страница») и происхождение («Локальная»/«Копия с сервера»);
2. редактируемую панель или страницу и область виджетов;
3. локальное состояние «Сохранена»/«Изменена»;
4. режим подключения: «Автономно», «Только чтение», «Чтение-запись»;
5. источник и его происхождение, если существует;
6. назначение и действие, если выбраны;
7. свежесть снимка и состояние публикации как независимые оси.

«Сохранена» не означает «опубликована»; «Чтение-запись» не означает наличие VerifiedPlan; источник не является назначением.

## 5. Конфликт существующего `project/v1` (O-026)

Текущая схема `zdashstitch.project/v1` требует `dashboards[]` с 1–16 элементами и не хранит вид `dashboard|page`. Поэтому она является многообъектным legacy exchange container и не может без дополнительного контракта быть единственным сериализованным представлением двух видов локального черновика. Имя формата техническое и в интерфейсе не показывается.

O-026 решено 24.10.2026 (`project/v2`, `kind: dashboard|page`, явная миграция v1). До реализации P0-08:

- существующие schema/fixtures/Rust/Python проверки остаются неизменными и читаемыми;
- UI не утверждает, что `project/v1` полностью сохраняет вид черновика и действие публикации черновика страницы;
- новые runtime-модели typed project и миграция формата не реализуются;
- P1 может проектировать экраны с явным видом черновика, но G1 handoff обязан пометить зависимость;
- P4 export и P5 create/append блокируются до выбора versioned representation и migration path.

## 6. Проверки приёмки

- Любой экран однозначно различает панель, страницу, виджет и происхождение черновика.
- В интерфейсе нет слова «проект»; термины совпадают с официальной русской локализацией Zabbix 7.4.
- Страницу можно извлечь из одной панели и направить в другую без подмены identity.
- Нет общей рабочей области, которая скрывает вид черновика.
- «Добавить страницу в панель» и «Добавить виджеты на страницу» требуют явной цели.
- Старый `project/v1` не переименован и не изменён без решения O-026 и обновления схем, генератора, fixtures, Rust/Python тестов и миграции.
