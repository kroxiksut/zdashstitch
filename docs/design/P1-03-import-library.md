## P1-03A — источники импорта и точки входа

| Источник | Где начинается | Результат | Требует |
|---|---|---|---|
| Панель в Zabbix целиком | «Панели в Zabbix» → «Скопировать с сервера» | снимок + черновик панели «Копия с сервера» | подключение |
| Одна страница панели в Zabbix | «Взять страницу» | снимок + черновик страницы «Копия с сервера» | подключение |
| Шаблоны Zabbix (несколько) | «Панели в Zabbix» → «Шаблоны» | по каталогу метрик на шаблон, в библиотеку | подключение |
| Файл панели или страницы `project/v2` | «Импорт файлов» | черновик панели или страницы «Локальная» | — |
| Пакет ZIP (DATA-ONLY) | «Импорт файлов» | черновик + каталоги метрик из пакета | — |
| Старый файл `project/v1` | «Импорт файлов» | черновик выбранной панели или страницы | явный выбор корня (O-026) |
| Экспорт шаблонов Zabbix 7.4 (YAML/JSON/XML) | «Импорт файлов» | каталоги метрик | — |
| Файл профиля оформления `zdashstitch.style-profile/v1` | «Импорт файлов» | профиль в библиотеке; совпадение идентификатора — явный выбор «Заменить (новая версия)» / «Сохранить как копию» (`version = max(local, file) + 1`) | — |
| Файл заготовки виджета `zdashstitch.widget-blueprint/v1` | «Импорт файлов» | заготовка в библиотеке; маски узлов, замещения, связи и неизвестные поля — отказ с кодом | — |
| Объект библиотеки (страница, снимок) | «Библиотека» | черновик страницы или копия | — |

Подзаголовок экрана «Импорт файлов» (02-02) — `import.files.subtitle` «Dashboard and page files, ZIP packages, Zabbix 7.4 template exports, style profiles and widget blueprints.» / «Файлы панелей и страниц, пакеты ZIP, экспорты шаблонов Zabbix 7.4, профили оформления и заготовки виджетов.» (определён в P1-06C–D); макет 02-02 — тот же текст.

- «Импорт файлов» принимает несколько файлов сразу: нативный диалог («Выбрать файлы…», O-023) или «Загрузить через браузер»; перетаскивание — тот же путь, что загрузка через браузер.
- До запуска для каждого файла показывается: как распознан, краткое содержимое и **что станет** (черновик панели, черновик страницы, N каталогов метрик, «не импортируется»). Ничего не добавляется «во всё сразу».
- Старый формат с несколькими панелями блокирует запуск, пока не выбрана одна панель или страница; исходный файл не меняется.
- Повторный импорт того же файла создаёт новый черновик; существующие не перезаписываются.

## P1-03B — объекты подключённого Zabbix

Раздел «Панели в Zabbix» имеет вкладки «Панели» и «Шаблоны».

Панели — таблица: имя, владелец («вы» / «другой пользователь»: имя чужого владельца Zabbix не сообщает не-Super admin, P1-IN-08), доступ («Личная»/«Общая»), страниц, виджетов, «Изменение» (сколько виджетов ZDashstitch умеет менять по реестру P0-09), «У меня» (есть ли копия и её дата). Фильтры «Все / Мои / Общие», поиск по имени. Справа — сведения о выбранной панели: страницы с числом виджетов, разбивка «изменение поддерживается / не поддерживается» по типам, существующая копия со ссылкой «Открыть копию», действия «Скопировать с сервера» (основное), «Взять страницу», «Клонировать», «Заменить узел сети». Каждое действие начинается с копии; сервер меняется только через «Публикацию».

Шаблоны — таблица с флажками: шаблон, группа шаблонов, «элементы · LLD · прототипы», наличие в библиотеке. Фильтр по группе и поиск. Справа — итог выбора: «Станет: N каталогов метрик, по одному на шаблон», что переносится и что нет, предупреждение о новой версии уже импортированного каталога, кнопка «Импортировать в библиотеку (N)».

| Состояние | Что видно |
|---|---|
| Загрузка | скелет строк; при задержке > 1 с — «Загрузка списка…» (P1-IN-06: обычно 50–200 мс) |
| Пусто | «Панели не найдены либо учётная запись не может их просматривать» — Zabbix не различает (P1-IN-08) |
| Частично | список как есть, постоянная оговорка про видимость |
| Без подключения | «Подключитесь к Zabbix, чтобы увидеть панели» и кнопка «Подключиться» |
| Нужен вход / нет связи | последний список не показывается как актуальный; «Войти» / «Повторить» |
| Тип не поддерживается | панель видна; «Изменение 0 из N»; копировать можно (копируется как есть) |
| Шаблон: пустой экспорт | строка «не найдено или нет доступа», каталог не создаётся (P1-IN-08) |

Zabbix templates, заготовки виджетов и снимки не смешиваются: шаблоны — источник каталогов метрик; заготовки виджетов — отдельный раздел библиотеки (P1-06).

### Предпросмотр панели на сервере (28.10.2026, решение владельца)

Макета нет: экран дополняет 03-01 текстом по решению владельца (P2-05E). В сведениях выбранной панели первое действие — «Предпросмотр» (`server.action.preview`); оно открывает `/server/:connection_local_id/preview` — панель только для просмотра, без копии.

- **Вид** — как «Структура» черновика (P1-01B §2a, макет 08-01): дерево «панель → страницы → виджеты» со свойствами панели и периодами страниц, предпросмотр страницы в пропорциях сетки 72 колонки с выбором ширины экрана. Действий структуры и редактора нет совсем — даже недоступных: панель на сервере на месте не меняется.
- **Шапка**: имя панели (серверные данные), отметка «Только просмотр», владелец и доступ, пояснение «на этом компьютере ничего не сохраняется; чтобы изменить панель, сначала скопируйте её». При существующей копии — «Есть копия от …» и «Открыть копию».
- **Действия**: «Скопировать с сервера» ведёт в проверку перед копированием (P1-03C, макет 03-03); «Взять страницу» с выбором страницы — тот же импорт страницы, что в сведениях панели (P2-05D). Других действий нет.
- **Данные**: тот же один `dashboard.get` выбранной панели, что и для сведений и проверки перед копированием, через read-only шлюз и защищённый API локального сервера; браузер не обращается к Zabbix. Ответ дополнен положением и размером виджетов, периодами страниц и свойствами панели. На диск ничего не пишется: ни снимка, ни черновика, ни кэша.
- **Адрес** не содержит Zabbix ID: выбранная панель живёт только в памяти, как у проверки перед копированием; после перезагрузки страницы — возврат к списку панелей.
- **Состояния**: загрузка — скелет; ошибка чтения — баннер `server.preview.load_failed` с действием восстановления по коду; без подключения или при другом активном подключении — те же состояния, что у «Панелей в Zabbix».

## P1-03C — объём и зависимости

Перед копированием панели (макет 03-03):

- **Состав** по страницам: число виджетов и разбивка «изменение поддерживается / копируется как есть», раскрытие до виджетов.
- **Зависимости**: узлы сети (число и имена), ссылки на элементы данных (по ID и по шаблону имени, P1-IN-02), графики, связи между виджетами (`reference`), неизвестные поля.
- **Что сохранится**: снимок (неизменяемый, база), черновик «Копия с сервера» (правки — отдельными операциями, O-018), владелец и доступ (для восстановления при публикации; в файлы и экспорт не попадают, O-031).
- **Не сохраняется**: значения метрик, данные узлов сети, пароли и токены.
- Панель читается дважды; если изменилась во время чтения — копия не создаётся (`import_inconsistent`, P2-05C).
- Если копия этой панели уже есть, основное действие — «Открыть мою копию»; «Новая копия» создаёт отдельную копию, существующая не меняется. Это же правило действует для «Заменить узел сети» и «Клонировать» из «Панели в Zabbix»: сначала предлагается продолжить в существующей копии. Одноимённые копии в списках различаются датой снимка. **28.10.2026 (решение владельца):** новая копия уже скопированной панели (страницы) по умолчанию получает имя «… (копия N)»; при совпадении имён в «Черновиках» и «Недавнем» рядом с именем показывается подключение-источник. Обновить базу существующей — «Скопировать заново» в её обзоре (P1-03E). (P1-11, 25.10.2026.)

Объём MVP: панель целиком (P2-05) или одна страница («Взять страницу»). Выбор отдельных виджетов — область действия «Добавить виджеты на страницу» (P1-04/P5), не вид импорта. Копия страницы хранит связи только внутри страницы; ссылки на виджеты других страниц показываются как «связь с виджетом вне страницы — не переносится» и требуют проверки в «Проверках».

Для шаблонов: элементы данных, правила LLD, прототипы, единицы, типы значений, макросы шаблона, сопоставления значений переносятся в каталог метрик; панели шаблонов (в MVP), триггеры и скрипты — нет (P1-IN-05).

## P1-03D — выполнение и результат

Этапы на объект: чтение → разбор → проверка → нормализация → сохранение. Прогресс показывает объект и этап («Чтение файла «{file_name}»…», «Обработано объектов: {completed} из {total}»). Порог показа прогресса — 1 с; экспорт шаблона может идти секунды (P1-IN-06: до 3,9 с первым вызовом).

- **Атомарность:** каждый файл или серверный объект сохраняется целиком (временный файл → `fsync` → rename, O-018) или не сохраняется совсем. Отмена до сохранения объекта ничего не оставляет; уже сохранённые объекты остаются и перечислены в итоге.
- **Итог по каждому объекту:** «Импортирован», «Частично» (с перечнем непереносимого), «Отклонён» (код правила), «Пропущен» (отменён или убран пользователем). Общий баннер не говорит «успешно», если есть частичные или отклонённые.
- Переходы: «Открыть» (черновик), «В библиотеку» (каталоги), «Ещё файлы», «К черновикам».
- «Копировать отчёт»: имена файлов, коды, этапы, счётчики и время; без содержимого файлов, путей на диске и данных узлов сети.
- Повтор: отклонённый файл можно исправить и импортировать снова; повтор начинается сначала.

## P1-03E — происхождение, снимки и повторное копирование

Карточка происхождения (в «Обзоре» копии и в сведениях объекта библиотеки): источник (панель/страница/шаблон или файл), подключение, версия сервера или формата файла, время получения, область, способ (чтение панели / экспорт конфигурации / файл), отпечатки — только в «Технических сведениях». Секретов и данных узлов сети в происхождении нет.

Свежесть копии — ось E из P1-01C (`not_checked/current/stale/conflict/source_missing`).

**«Скопировать заново»** (макет 07-02): новая база читается как новый снимок; прежняя сохраняется. Локальные операции (O-018) переигрываются на новой базе:

| Итог операции | Когда | Действия |
|---|---|---|
| Применилась | цель на месте, поле не менялось на сервере | — |
| Конфликт | на сервере изменено то же поле или виджет | «Оставить серверное» / «Применить моё»; выбор попадает в «Мои изменения» и виден перед публикацией |
| Цель исчезла | виджет или страница удалены на сервере | «Убрать правку»; «Показать прежнюю базу» |

Пока есть нерешённые случаи, «Принять новую базу» недоступна, черновик остаётся на прежней базе; «Вернуться к прежней базе» отменяет переигрывание без потерь. Молчаливого слияния нет (O-014). Сервер не меняется.

Операция `apply_style_profile` переигрывается по полям: поле, изменённое на сервере, — «Конфликт» с теми же действиями; виджет, исчезнувший на сервере, — «цель исчезла». Операции с `service: true` (метка у источника после извлечения, P1-06C) переигрываются без конфликтов и в отчёте не показываются.

**Одна кнопка — одно поведение (B-01, В-20).** «Скопировать заново» — единственная подпись и единственный ID (`workcopy.refetch.action`) этого действия везде, включая конфликт в «Публикации» (P1-08D, макет 11-05): оттуда оно ведёт на этот же экран 07-02 с переигрыванием правок. Прежний ID `publication.conflict.action.reimport` («Скопировать панель заново») не используется. Второй, отдельный вариант при конфликте — «Новая копия» (`copy.action.new_copy`, как в P1-03C): новая рабочая копия с нового снимка **без** переноса правок; этот черновик и его база остаются как есть.

Версии каталога метрик: повторный импорт шаблона создаёт новую версию; прежняя хранится, пока её используют черновики; удалить можно только неиспользуемую.

## P1-03F — черновики и библиотека

**«Черновики»** (макет 02-01) — все локальные панели и страницы. Фильтры: вид («Панели»/«Страницы»), происхождение («Локальные»/«Копии с сервера»), поиск. Колонки: имя, тип, происхождение, источник, состояние (локальное «Сохранена/Изменена» и для копий — свежесть). Сортировка по времени изменения.

Сведения о черновике: тип и происхождение, источник, подключение, база, свежесть, локальное состояние; «Создано из этой копии» — панели, созданные публикацией (O-022), с отметкой проверки повторным чтением; у локального черновика тот же блок называется «Создано из этого черновика» и берётся из `deployment-state/v1` (дополнение P1-08 A.1). Действия: «Открыть», «Дублировать», «Переименовать», «Сделать переносимой для экспорта…» (для копии с сервера — преобразование P1-07I; у локальных — «Экспорт в файл»), «Сохранить страницу в библиотеку» (у черновика страницы и у выбранной страницы панели в «Структуре», решение В-7), «Удалить».

Безопасное удаление: подтверждение с именем; удаление не трогает сервер; снимок удаляется, только если на него не ссылаются другие копии и журнал; запись журнала остаётся. Черновик с незавершённой операцией журнала удалить нельзя до сверки.

**«Библиотека»** (макет 04-01) — разделы по типу объекта: «Снимки», «Страницы» (сохранённые для повторного использования, O-027), «Каталоги метрик», «Профили оформления» и «Заготовки виджетов» (P1-06C). Черновиков в библиотеке нет.

Откуда берутся «Страницы» (M-10, решение В-7): файл страницы при импорте становится черновиком (P1-03A), а в библиотеку страница попадает действием «Сохранить страницу в библиотеку» (`drafts.action.save_page_to_library`) — у черновика страницы в «Черновиках» и у выбранной страницы панели в меню страницы «Структуры» (P1-01B §2a). В библиотеку кладётся копия страницы на момент действия (черновик от неё не зависит); при сохранении страницы копии с сервера сначала выполняется преобразование P1-07I для одной страницы, ссылки на сервер в библиотеку не попадают. Одноимённые страницы различаются временем сохранения; повторное сохранение не перезаписывает прежнюю. Из раздела страница берётся в работу «Взять страницу» (новый черновик страницы) или «Добавить страницу в панель» (P1-01I).

| Раздел | Колонки | Действия | Удаление |
|---|---|---|---|
| Снимки | панель/страница, подключение, время, на что ссылаются | открыть копию, сравнить с текущей базой | только без ссылок |
| Страницы | имя, источник (черновик, из которого сохранена), виджетов, сохранена | «Взять страницу», «Добавить страницу в панель», «Переименовать» | всегда (черновики не зависят) |
| Каталоги метрик | каталог, источник, версия, кто использует | обновить с сервера (новая версия), переименовать | только неиспользуемые |
| Профили оформления | имя, типы виджетов, версия, используют (виджеты · черновики), происхождение или состояние | «Изменить профиль» (P1-06E), «Дублировать», «Переименовать», «Экспорт в файл…», «Создать профиль» в заголовке «Библиотеки» (окно выбора разделов и «на основе встроенного») | всегда (черновики не зависят; предупреждение об использовании) |
| Заготовки виджетов | имя, тип, параметры (роли · метрики), размер, версия, происхождение или состояние | «Дублировать», «Переименовать», «Экспорт в файл…»; создаются только из виджета в редакторе, вставляются через «Добавить виджет» → «Из заготовок» (P1-06F) | всегда (вставленные виджеты не зависят) |

Встроенных профилей два — эталоны «Рост БД — столбцы» и «Нагрузка CPU — линия» (P1-06A §12), только чтение, «Дублировать» даёт изменяемую копию; встроенных заготовок нет.

Orphan-состояния: копия, у которой исчез источник на сервере, — «Источник не найден» (свежесть `source_missing`), работает как локальная; созданная из копии панель, удалённая на сервере, — «не найдена при последней проверке» в списке «Создано из этой копии». Названия Prod/Pilot/Test — только данные пользователя, на навигацию не влияют.

## P1-03G — безопасность файлового импорта

Файлы — недоверенные данные: проверка в памяти без распаковки на диск, без выполнения скриптов, загрузки внешних ресурсов и сетевых ссылок (`import.security.untrusted`). Отказ — по стабильному коду `core` (P1-IN-05), текст — по карте ошибок P1-00F §3.

| Класс | Коды | Что видит пользователь | Сохраняется |
|---|---|---|---|
| Правила пакета | `archive_*`, `relative_path`, `duplicate_archive_entry`, `entry_size`, `total_size`, `compression_ratio`, `file_type` | «Файл отклонён правилами безопасности импорта ({code})» и короткое пояснение | ничего |
| Опасная структура | `yaml_depth`, `yaml_alias`, XML DTD/внешние сущности (P4-01) | «Файл содержит запрещённую структуру ({code})» | ничего |
| Разбор | ошибки YAML/JSON/XML (код вводится, P1-IN-05 «пробел») | «Не удалось разобрать файл {format}» и строка/столбец, если известны | ничего |
| Схема и связи | `duplicate_*`, `unknown_*`, `layout_*`, `legacy_root_not_found`, `invalid_version_range` | «Данные противоречивы ({code})» и путь к объекту | ничего |
| Неизвестный формат | — | «Не распознан» до запуска; файл не импортируется | ничего |
| Частично переносимое | панели шаблонов, неизвестные типы виджетов | «Частично» с перечнем | переносимое; неизвестные виджеты — как есть |

Карантина как отдельного хранилища нет: отклонённый файл не сохраняется вовсе, поэтому «изолировать» нечего. Содержимое файлов не пишется в журналы и отчёты. Переносимый файл не считается обезличенным (AGENTS.md §3) — это отдельный вопрос экспорта (P1-07).

## Проверки приёмки P1-03

- Выбранную панель можно скопировать целиком и открыть без подключения со всеми настройками; неизвестные виджеты и поля сохраняются как есть.
- Одна страница и несколько шаблонов выбираются отдельно; несколько файлов импортируются за раз, у каждого виден результат.
- Частичная поддержка и отказы видны по каждому объекту; общий итог не называет частичный импорт успешным.
- Повторное копирование не уничтожает локальные правки: они переигрываются, конфликты решаются вручную, прежняя база сохраняется.
- Шаблоны Zabbix, заготовки виджетов, снимки и черновики не смешиваются; черновики — только в «Черновиках»; страницы библиотеки появляются только действием «Сохранить страницу в библиотеку».
- Без подключения нет имитации живых данных; список панелей сервера не показывается как актуальный.
- Отклонённый файл ничего не сохраняет; содержимое файлов не попадает в отчёты и журналы.
