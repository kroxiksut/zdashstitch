# Z80-P0-05 — синтетические fixture и матрица контрактов 8.0

Дата: 17.11.2026. Точный patch и отдельная лаборатория Zabbix 8.0 **не установлены**. Ни один файл здесь не является захватом ответа сервера или обезличенной корпоративной панелью. Все ID, имена, ключи и значения вымышлены. Это локальные сценарии для будущей проверки на разрешённом стенде, а не доказательство формы каждого ответа установленной 8.0.

## Источник и назначение данных

- [`fixtures/zabbix/8.0/dashboard-get-synthetic.json`](../../fixtures/zabbix/8.0/dashboard-get-synthetic.json): иллюстративный `dashboard.get` document: `item`, `svggraph` с полями item tags, классический `graph` с `show_hostnames`, новый `scatterplot`, неизвестный виджет, ссылки и непрозрачные расширения. Названия полей и наличие `scatterplot` сверены с [официальным списком изменений API 8.0](https://www.zabbix.com/documentation/8.0/en/manual/api/changes); конкретные сочетания значений не получены из лаборатории.
- [`fixtures/zabbix/8.0/item-inventory-synthetic.json`](../../fixtures/zabbix/8.0/item-inventory-synthetic.json): обычный item рядом с `value_type=6`, discovered item и JSON item prototype. Это иллюстрация класса смешанного inventory, а не эталон полного ответа `item.get`/`itemprototype.get`. Значение 6 описано [официальным экспортом шаблонов 8.0](https://www.zabbix.com/documentation/8.0/en/manual/config/xml_export_import/templates); нормализованный `metrics/v2` регулирует отдельный Z80-P0-04.
- [`fixtures/zabbix/8.0/dashboard-negative-synthetic.json`](../../fixtures/zabbix/8.0/dashboard-negative-synthetic.json): четыре локальных отказа на неверной обязательной форме. Они не моделируют API ошибки прав, роль или поведение сервера.
- Rust `z80_p0_05_fixtures` проверяет сохранение raw, обнаружение/unknown без разрешения на изменение, ошибки формы, закрытый server gate и регрессию существующего 7.4 fixture. Синтетический тест не подменяет независимый лабораторный контракт.

## Матрица по виджетам и операциям

`Closed` означает отсутствие разрешения adapter capability в 8.0. «Локально» относится только к указанному fixture и тесту. Для каждого будущего допуска нужны отдельные read, modify, create/copy и read-back доказательства на точном patch, включая роль и запрет утраты незатронутых полей.

**Важная граница классификации:** `VersionedDashboardSnapshot::analyze` сейчас вызывает общий `analyze`, который по именам `item`/`svggraph`/`graph` ставит `DiscoveredReadOnly` независимо от версии и пустого реестра 8.0. Это эвристика для локального JSON, а не проверенный контракт чтения 8.0 и не `SupportedForModification`. Пока нет отдельного 8.0 read gate, даже строки с `DiscoveredReadOnly` ниже имеют `Closed`.

| Объект / операция | Документация 8.0 | Синтетический fixture и локальная проверка | Лабораторный контракт 8.0 | Текущая 8.0 capability |
|---|---|---|---|---|
| `item`: raw snapshot и itemid | Тип известен API | `dashboard-get-synthetic`; raw/dependency в `synthetic_dashboard_preserves_new_and_opaque_fields_without_authority` | Нет: разрешённое чтение, полный payload, права | Closed: серверный read и modify/create |
| `svggraph`: itemids, host pattern, новые item tags | [API changes](https://www.zabbix.com/documentation/8.0/en/manual/api/changes) перечисляет `ds.0.item_tags*` | То же; сохранение raw полей и отчёт о ссылках без редактирования | Нет: отдельные read, mask resolution, update/copy/read-back для новых полей | Closed: read, edit, create/copy |
| `graph`: graphid и `show_hostnames` | [API changes](https://www.zabbix.com/documentation/8.0/en/manual/api/changes) перечисляет `show_hostnames` | То же; raw сохраняется | Нет: graph lookup, update/copy/read-back и сохранность нового поля | Closed: read, edit, create/copy |
| `scatterplot` | [API changes](https://www.zabbix.com/documentation/8.0/en/manual/api/changes) перечисляет тип | То же; классифицирован `Unknown`, raw сохранён | Нет: payload, зависимости, поля, safe copy/update | Closed, неизвестный виджет |
| `vendor.synthetic` и неизвестные поля | У API нет контракта для вымышленного расширения | То же; raw сохраняется и классификация `Unknown` | Нет: отсутствие потерь на конкретном сервере и при конкретной операции | Closed, unknown blocks mutation |
| Item / prototype inventory `value_type=6`, LLD | [Экспорт 8.0](https://www.zabbix.com/documentation/8.0/en/manual/config/xml_export_import/templates) задаёт JSON (6) | `item-inventory-synthetic`; проверка различимости JSON/обычного item и LLD в `synthetic_inventory_keeps_json_and_lld_distinct_but_server_gate_stays_closed` | Нет: смешанный ответ с полными полями, права, парсер 8.0, экземпляр прототипа | Closed: серверный read; `metrics/v2` не даёт publish |
| Неверная форма snapshot | Не является утверждением о поведении API | `dashboard-negative-synthetic`; четыре отказа в `malformed_synthetic_dashboard_cases_fail_closed` | Нет: API error shapes и неполная выдача отдельно | Closed |
| `apiinfo.version`, auth, роли, restricted reads | [Upgrade notes 8.0](https://www.zabbix.com/documentation/8.0/en/manual/whatsnew) меняют правила API ролей | Существующие `eight_zero_profile_is_refused_before_credentials_are_sent` и `eight_zero_profile_has_no_server_or_widget_authority` проверяют отказ до credential; role fixture здесь нет, поскольку семантика не реализована | Нет: точный patch, новый/обновлённый режим, allow/deny/wildcard, смена прав | Closed: `resolve_server(8.0)` возвращает UnsupportedVersion |
| `dashboard.update`, `dashboard.create`, append/copy, publish | Документация описывает методы, но не доказывает сохранность payload | Локальный тест проверяет только отсутствие `SupportedForModification` и пустой 8.0 registry | Нет: отдельные P0/P5 write, permission, conflict, one-send, unknown outcome, read-back | Closed: нет 8.0 write/copy authority |
| Регрессия 7.4 | Отдельные ранее полученные доказательства 7.4.16 | `seven_four_fixture_remains_bound_to_its_profile` + существующий пакет 7.4 тестов | Исторические контракты 7.4.16; не переносятся на 8.0 | Существующий 7.4 профиль не меняется |

Следующий шаг по зависимостям: Z80-P0-05 представить отдельно на приёмку; 8.0 read/auth и лабораторные контракты выполнять отдельными задачами после определения стенда и точного patch. Для перехода от `Closed` к конкретной возможности потребуется отдельный исполняемый тест на разрешённой 8.0, проверка результатов и решение по соответствующему gate. Python reference проверяет переносимые форматы, не этот API fixture.
