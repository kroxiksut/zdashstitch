# Z80-01 — отличия Zabbix 7.4 и 8.0 для ZDashstitch

Дата: 17.11.2026. Статус: исследование по официальной документации и локальному коду; не лабораторное подтверждение и не заявление поддержки 8.0. Точный patch рабочего сервера и лаборатория 8.0 пока не подтверждены. Сведения о 7.4.16 ниже относятся только к ранее испытанному лабораторному стенду.

## Правила перехода

Основная цель — 8.0, результаты 7.4 сохраняются. `core`, журнал, представление намерений, локальные черновики и механизмы работы с недоверенными файлами должны по возможности оставаться общими. Версионные сведения API, регистра виджетов, кодеков, прав и доказательств операций выбираются явно по целевому адаптеру. Повторное использование реализации не переносит свидетельства испытаний. Никакого fallback с 8.0 на 7.4, выключения TLS или допуска write по одному номеру версии.

## Подтверждённые различия и последствия

| Область | Официальные сведения 8.0 | Фактическое состояние проекта / действие |
|---|---|---|
| Выбор версии | `apiinfo.version` возвращает версию API, соответствующую серверу. [API](https://www.zabbix.com/documentation/8.0/en/manual/api) | `crates/zabbix/src/capabilities.rs` сейчас допускает только 7.4; 8.0 отвергается. Отдельный профиль/реестр 8.0, тесты отказов и сохранение регрессий 7.4. |
| Права API | В новых установках доступ к API по умолчанию отключён для всех ролей; в обновлённых — для новых ролей. Пустой allow list в 8.0 запрещает все методы; при обновлении ранее пустые allow lists получают `*`. [Upgrade notes](https://www.zabbix.com/documentation/8.0/en/manual/whatsnew) | `create_permission.rs` допускает пустой список в 7.4.16 и специально ограничен этим patch. Реализовать раздельные правила по версии, лабораторно проверить роли, wildcard, deny/allow, отсутствие доступа и смену прав перед записью. Не копировать старую семантику. |
| Виджеты и графики | 8.0 добавляет поля item tags для `svggraph`/`piechart`, `show_hostnames` для graph, поля topitems и geomap, а также `scatterplot`. [API changes](https://www.zabbix.com/documentation/8.0/en/manual/api/changes) | `WidgetCapabilityRegistry::v7_4()` встречается в `application` и `zabbix`, в том числе при материализации и импорте. Вынести выбор версии/контекста, не регистрировать новые поля как проверенные только по документации. Неизвестное блокирует изменение согласно контракту. Сохранение нетронутых полей и ссылок — отдельный лабораторный контракт 8.0. |
| JSON-метрики и LLD | `item` и `itemprototype` получают `value_type = 6` (JSON); добавлены поля и тип telemetry query. [API changes](https://www.zabbix.com/documentation/8.0/en/manual/api/changes) | `lookups.rs` принимает `value_type <= 5`, `core::formats::ValueType` не содержит JSON, импорт понимает только значения 0–5. Не подменять JSON текстом, не терять исходный тип. Добавление в переносимый формат требует отдельного решения владельца, схемы и совместимости; до этого неподдерживаемый объект должен диагностироваться безопасно. Проверить влияние на соседние допустимые метрики и LLD-экземпляры. |
| Экспорт шаблонов | Документация показывает `zabbix_export.version: 8.0` и поддерживает YAML/JSON/XML. [configuration.export](https://www.zabbix.com/documentation/8.0/en/manual/api/reference/configuration/export) | `template_import/src/lib.rs` жёстко требует `7.4` и записывает эту версию в метаданные. Нужен отдельный детектор/профиль 8.0, реальные обезличенные или синтетические эталоны всех трёх форматов, сравнение результатов и негативные случаи; не менять маркер файла на лету. |
| Панели в экспорте | 8.0 позволяет экспортировать/импортировать панели; `configuration.export` принимает `dashboards`. [Что нового](https://www.zabbix.com/documentation/8.0/en/manual/whatsnew), [export API](https://www.zabbix.com/documentation/8.0/en/manual/api/reference/configuration/export) | Исследовать экспорт как read-only вход и сопоставить с `project/v2`, но не смешивать их форматы. `configuration.import` — отдельный универсальный write API, не входит в существующий dashboard-only allowlist; его применение требует отдельного решения о безопасности и испытаний. Новое штатное средство не заменяет согласованные сценарии многосерверных графиков и перепривязки без анализа. |
| Создание, update, ownership, ссылки | Из документации нельзя вывести доказательство сохранности конкретного dashboard payload и семантики прав на установленном patch. [Dashboard API](https://www.zabbix.com/documentation/8.0/en/manual/api/reference/dashboard) | Существующие `VerifiedCreatePlan`/`VerifiedPlan`, журнал и механизмы отказа могут переиспользоваться, но профили `dashboard.create/update`, read-back, конфликт, ambiguous outcome, приватность, права и ссылки должны иметь отдельные 8.0 fixtures и lab-контракты. До них write закрыт; P5-07 и P5-08 не считать принятыми для 8.0. |
| Маски и видимость | Результаты API зависят от прав аккаунта; версия сама не доказывает видимость всех данных. [API](https://www.zabbix.com/documentation/8.0/en/manual/api) | Текущий обзор масок ограничен видимыми узлами и отказывает при усечении. Требуются отдельные 8.0 тесты семантики `svggraph`, внешних совпадений, скрытых узлов и смены результата между планом и отправкой. Запись графиков до доказательств блокируется. |

## Очередь реализации и проверки

1. Инвентаризировать все вызовы `WidgetCapabilityRegistry::v7_4()` вне тестов; определить, где нужен выбранный профиль сервера, а где автономный импорт требует явной версии источника. Заменять их с регрессионной проверкой 7.4, не одним глобальным реестром 8.0.
2. Построить `v8_0` как отдельный профиль с неизвестными возможностями по умолчанию; общие parser/transport/types — через композицию. Прогнать `apiinfo.version`, авторизацию и read-only mock тесты 7.4/8.0/неподдерживаемой версии; version-specific роль и пустые списки проверять отдельно. Не включать write без пункта 4.
3. Подготовить данные для шаблонного импорта 8.0: YAML/JSON/XML, несколько шаблонов, LLD, неизвестные и JSON-элементы, некорректные версии, дубликаты, алиасы/внешние сущности и пределы размера. Поддержку JSON в переносимом каталоге согласовать отдельно.
4. На отдельно разрешённой лаборатории 8.0 определить точный patch и проверить P5-07, create/update/read-back/reconciliation, графики, LLD, маски, права и негативные случаи. Пользователь разрешил ранее запускать VM 7.4, но наличие отдельного стенда 8.0 и разрешение модифицировать его нельзя предполагать.
5. Реализовывать многосерверные графики и P5 поверх подтверждённых capabilities, с повторными проверками перед единственной записью. Сравнить поведение 7.4 и 8.0 на одном намерении; без доказательств возвращать отказ, а не урезать данные.

## Начальная матрица операций

Здесь «проверить» — задача, не разрешение операции. Для 7.4 перечислены только свидетельства в текущем плане; отсутствие отдельного доказательства означает, что готовность не утверждается.

| Операция | 7.4 | 8.0: что нужно до допуска |
|---|---|---|
| Определение версии и вход | Реализовано для семейства 7.4; конкретные возможности зависят от patch | Тесты `apiinfo.version`, unsupported/prerelease и авторизации, отдельный профиль; запрет отправки учётных данных неподдержанному серверу до проверки версии |
| Чтение inventory/snapshot | Реализовано для 7.4; права могут скрывать данные | Тесты разрешённого и ограниченного аккаунтов, неполной выдачи, неизвестных полей, `value_type=6`, ссылок и целостности raw snapshot |
| Файловый импорт шаблона | Парсер проверяет маркер 7.4; YAML/JSON/XML | Три эталонных файла 8.0, несколько каталогов и LLD, негативные проверки, явная версия; JSON-type до O-041 остаётся неподдерживаемым |
| ReplaceHost / `dashboard.update` | Есть узкие лабораторные контракты 7.4.16; полнота остальных сценариев не подразумевается | Матрица по каждому типу виджета и полю, сохранение страниц/прав и неизвестных данных, конфликт снимка и read-back на 8.0 |
| Clone / `dashboard.create` | Есть узкие контракты 7.4.16 и отдельные открытые проверки | Проверить личную панель, имя/права, несколько рядов и LLD, целевые роли/слоты, read-back и неизвестный результат |
| Portable create / P5 | Защищённый механизм частично реализован; графики и маски не допущены | Версионная materialization и codec, повторная проверка метрик/масок и всех видимых совпадений, неподтверждённые/скрытые данные блокируют запись |
| Append / Update и deployment state | Не считать завершёнными без критериев P5 | Отдельные capability и лабораторные контракты 8.0; journal и fingerprints можно переиспользовать при сохранении привязки к версии и источнику |
| Общий доступ и владелец / P5-08 | Результаты 7.4.16 не устанавливают поведение другой версии | Держать отдельный lab gate; до принятия создавать только личные панели |
| Dashboard export / import 8.0 | Не считать встроенный формат эквивалентным `project/v2` | Проверить файл и ограниченный read-only export; `configuration.import` остаётся вне write allowlist до отдельного решения |

## Границы этого исследования

Документация не заменяет реальные ответы целевого patch; точное покрытие новых полей, экспорта панелей, прав и LLD требует fixtures и лаборатории. Это исследование не меняет схемы, write allowlist или runtime и не подтверждает готовность 8.0. XERJ-запросы: `AdapterRegistry`, `dashboard_create_permission`, `inspect_template_file`, `WidgetCapabilityRegistry`, `verify_portable_dashboard_create`; индекс сообщил об устаревании, выводы проверены по текущим файлам.
