## P1-06C — библиотека профилей и заготовок

### 1. Точки входа

| Откуда | Куда | Условие |
|---|---|---|
| «Библиотека» → раздел «Профили оформления» / «Заготовки виджетов» (P1-03F; разделы уже в навигации 04-01, снимается подпись «появятся позже») | список раздела (14-01, 14-02) | всегда, подключение не нужно |
| «Импорт файлов» (P1-03A) с файлом `zdashstitch.style-profile/v1` или `zdashstitch.widget-blueprint/v1` | распознанный вид «Профиль оформления» / «Заготовка виджета» → объект в библиотеке (14-03) | — |
| кнопка «Импорт файлов» в «Библиотеке» | тот же экран «Импорт файлов» с хлебными крошками «Библиотека / Импорт файлов»; итог «В библиотеку» возвращает в раздел созданного объекта | — |
| редактор страницы: «Сохранить оформление как профиль» / «Создать заготовку…» (P1-06D) | после сохранения — ссылка «Показать в библиотеке» на карточку объекта | виджет с флагом `edit` |
| инспектор: подпись «из профиля «{profile}»» (P1-06A §3.1) | ссылка на карточку профиля | профиль не удалён |
| «Создать профиль» в «Библиотеке» | редактор профиля P1-06E с пустым профилем (эталоны §12 P1-06A — как «Встроенные») | — |

Заготовку из библиотеки создать «с нуля» нельзя: единственный способ — из виджета в редакторе (P1-06D). Это ограничение показано подписью в разделе, а не недоступной кнопкой.

### 2. Разделы и список

Оба раздела используют компоновку 04-01: подразделы слева, список в центре, карточка справа. Общая кнопка «Импорт файлов» и «Создать профиль» — в заголовке «Библиотеки».

| | «Профили оформления» (14-01) | «Заготовки виджетов» (14-02) |
|---|---|---|
| Фильтр по типу виджета | «Все» / «График» / «Значение элемента данных» (типы с флагом `edit`; профиль может содержать оба) | те же (у заготовки ровно один тип) |
| Фильтр по происхождению | «Встроенные и мои» / «Мои» / «Встроенные» / «Из файла»; встроенных профилей два — эталоны P1-06A §12 «Рост БД — столбцы» и «Нагрузка CPU — линия» (решение В-17), других нет | «Любое происхождение» / «Мои» / «Из файла» (встроенных заготовок в MVP нет — вопрос 3) |
| Поиск | по имени, описанию, тегу; без учёта регистра; совпадение подчёркивается в имени | то же |
| Сортировка | по имени (по умолчанию) · по времени изменения · по использованию | по имени · по времени изменения · по числу вставок |
| Колонки | имя · типы виджетов · версия · используют («виджеты · черновики») · происхождение или плашка состояния | имя · тип · параметры («N ролей · M метрик») · размер · версия · происхождение или плашка |
| Выбор строки | открывает карточку; выбор не равен фокусу (P1-03H) | то же |

Происхождение в списке: «мой» (создан на этом компьютере), «встроенный» (поставляется с приложением), «из файла» (импортирован). Вместо происхождения строка показывает плашку состояния, если оно важнее: «Не проверено» (файл для другого адаптера, §6) или «Ошибка в поле» (`profiles.field.invalid`, P1-06B §7). Состояние не передаётся только цветом: плашка с текстом, в карточке — причина.

Счётчик «используют» считается по локальным меткам происхождения (P1-06A §3.3) и локальному журналу вставок заготовок; это локальные сведения, в файл объекта не попадают (`library.local_meta`).

Чего в карточке нет никогда: ID сервера, подключение, узлы сети, элементы данных, учётные данные (P1-06A §2). Имя автора не хранится и не показывается: происхождение — «здесь» или «из файла» (без имени пользователя ОС, O-031 не расширяется).

| Действие | Профиль | Заготовка | Правила |

| «Переименовать» | имя и описание; имя — не идентичность | то же | пустое имя не допускается (`profiles.name.required`); совпадение с другим именем — предупреждение, не ошибка (`profiles.name.taken`) |

Все действия локальные; сервер не меняется. Каждое сохранение **полей** профиля увеличивает `version` (P1-06A §4); переименование, описание, теги и дублирование версию не меняют — меняется только `updated_at` (Q19, P1-06H §14 п. 1).

### 5. Импорт и экспорт как отдельные файлы

Профили и заготовки **не входят** в DATA-ONLY ZIP черновика и из пакета не читаются (O-021, P1-06A §4). Импорт идёт через существующий «Импорт файлов» (P1-03A/G): файл распознаётся по полю `format`, проверяется в памяти по схеме и правилам P1-03G, показывается «что станет» (14-03). Новые строки для таблицы источников P1-03A — в разделе «Что изменится в принятых документах».

| Случай | Распознан как | Станет | Что видно до запуска |
|---|---|---|---|
| `zdashstitch.style-profile/v1`, `profile_id` в библиотеке нет | «Профиль оформления» | «профиль в библиотеке» | имя, типы виджетов, версия файла |
| `zdashstitch.widget-blueprint/v1`, нового `blueprint_id` нет | «Заготовка виджета» | «заготовка в библиотеке» | имя, тип, число параметров, диапазон совместимости |
| тот же `profile_id` / `blueprint_id` уже есть | то же | нужен выбор | `profiles.import.exists` / `blueprints.import.exists` с деталями (`profiles.import.exists_detail`); переключатели «Заменить (новая версия)» / «Сохранить как копию»; выбор обязателен — без него «Импортировать» недоступна, как для старого формата P1-03A |
| файл с `adapter`, которого нет в приложении (например, «8.0») | то же | «профиль в библиотеке» + плашка «Не проверено» | `profiles.state.unknown_adapter_hint`: сохранится, применить нельзя (уровень `unknown` P1-06B §7) |
| `format` с более новой версией (`…/v2`) | «Не распознан» | «не импортируется» | `profiles.import.newer_format`; файл не изменяется |
| схема нарушена (неизвестный ключ, недопустимое значение, `widget_types` пуст, `show` пуст у `item`) | вид по `format` | «не импортируется» | «Данные противоречивы ({code})» по карте P1-00F §3; коды — `core` |
| заготовка с именем или маской узла в поле-ссылке, `or.*`, `_reference`, неизвестным полем | «Заготовка виджета» | «не импортируется» | коды `blueprint_host_pattern`, `blueprint_override`, `blueprint_reference`, `blueprint_unknown_field` (новые коды `core` для схемы заготовки; текст — `errors.import.blueprint_host_pattern` и аналоги) |
| версия в файле ниже версии в библиотеке | то же | нужен выбор | `profiles.import.older_version`: замена всё равно даёт новую версию `local + 1` |

Правила замены и копии:

- **Заменить (новая версия):** идентификатор сохраняется, `version` становится `max(local, file) + 1`, локальная карточка (использование, происхождение «из файла», время) обновляется; черновики не меняются; у виджетов «из профиля» появляется `profiles.field.origin.outdated` (P1-06A §3.2). Если версия в библиотеке «мой» и изменена позже файла — предупреждение в строке, выбор остаётся за пользователем.
- **Сохранить как копию:** новый идентификатор, имя «{name} (импорт)», версия 1, происхождение «из файла»; существующий объект не трогается.
- Повторный импорт файла **без** конфликта идентификатора создаёт новый объект (как у черновиков, P1-03A); идентификатор — единственный признак «того же» объекта, имя — нет.
- Атомарность, отчёт и отказ — как P1-03D/G: отклонённый файл ничего не сохраняет, содержимое файла не попадает в отчёт.

### 6. Состояния

| Состояние | Где | Что видно | Действия |
|---|---|---|---|
| Пусто | раздел | `profiles.empty` / `blueprints.empty` с двумя путями: из редактора и из файла; кнопки «Импорт файлов», «Создать профиль» (только профили) | — |
| Загрузка | раздел | скелет строк; при задержке > 1 с — `common.state.loading` (индекс `library-index.json` читается локально, обычно мгновенно) | — |
| Ошибка чтения объекта | строка и карточка | строка остаётся с плашкой «Недоступен» и кодом (`errors.library.unreadable`); карточка — код, путь только в «Технических сведениях»; объект не изменяется | «Удалить» (с подтверждением), «Повторить» |
| Поиск без результатов | список | `library.search.no_results` с запросом; фильтры остаются | «Сбросить поиск» |
| Не проверено (`unknown`) | строка, карточка | плашка «Не проверено», причина `profiles.state.unknown_adapter_hint`; «Изменить профиль» и экспорт недоступны (`unknown` не редактируется, чтобы не выдумывать поля чужого адаптера), «Дублировать» недоступно по той же причине | «Переименовать», «Удалить» |
| Ошибка в поле (`invalid`) | строка, карточка | плашка «Ошибка в поле», `profiles.state.invalid_hint` с числом полей; применить нельзя (P1-06B §7) | «Изменить профиль» (P1-06E показывает ошибки у полей) |
| Встроенный | карточка | «Встроенный объект приложения»; «Изменить», «Переименовать», «Удалить» недоступны с подписью `profiles.origin.builtin_hint` | «Дублировать», «Экспорт в файл…» |
| Удаление используемого | подтверждение | имя, `profiles.used_by`, `profiles.delete.in_use` | «Удалить» / «Отмена» |
| Конфликт при импорте | «Импорт файлов» | §5 | «Заменить» / «Сохранить как копию» |
| Файл для другого адаптера, файл новее приложения, схема нарушена | «Импорт файлов» | §5 | — |
| Экспорт: файл существует | диалог экспорта | по настройке `export.on_existing_file` (P1-09G): спросить или новое имя; молча не перезаписывается | — |
| Форматы не утверждены (`/v0`) | карточка | «Экспорт в файл…» недоступна с `common.state.coming_later`; импорт файлов `/v0` не предлагается | — |

## P1-06D — создание из существующего виджета

### 7. Точки входа и условия

| Действие | Где | Доступно, если | Иначе |
|---|---|---|---|
| «Сохранить оформление как профиль» (`profiles.action.extract`, текст меняется — см. message IDs) | инспектор виджета (раздел «Основное», меню «Ещё»); меню виджета на холсте; при выборе нескольких виджетов — для всех выбранных | тип с флагом `edit` реестра P0-09 (`svggraph`, `item`), виджет `registry_state: known`, виджет хранится в общем виде `type: zabbix` (O-012 п. 5) | тип без `edit` или неизвестный — действие не показывается (`common.state.edit_unsupported` в инспекторе уже есть); типизированный вид `graph`/`item_value` старого файла — действие доступно, но извлекается только цвет рядов с подписью `profiles.extract.blocked.legacy_view` |
| «Создать заготовку…» (`blueprints.action.create`) | там же | тип с `edit` и `create` (`svggraph`, `item`), один виджет | несколько выбранных — действие недоступно с подписью «одна заготовка — один виджет»; `clock`/`problems` — не показывается (P1-06A §5) |
| в рабочей копии с сервера | то же | те же условия; источники у копии — реальные узлы и элементы (P1-05): для заготовки они **обязательно** заменяются параметрами (§9), для профиля не нужны | — |

Оба действия читают виджет и ничего в черновике не меняют (исключение — локальная метка происхождения у источника профиля, §8.5). Шага истории нет: метка у источника — **неотменяемая служебная операция** (решение В-16), как граничные строки матрицы P1-04G §4.3; Ctrl+Z её не снимает, снять метку можно только «Отвязать от профиля» (P1-06G §6.1). Подключение не требуется.

### 8. «Сохранить оформление как профиль» (14-04)

#### 8.1 Классы полей

Окно показывает поля виджета по классам матрицы P1-06B §8–§10, в порядке разделов инспектора P1-04D (Отображение → Оси и пороги → Основное для `view_mode`):

| Класс | Группа в окне | По умолчанию | Элемент | Что показано |
|---|---|---|---|---|
| профиль | «В профиль · N» | включено | флажок | человеческое имя поля (ID подписи из описания формы P1-04D), текущее значение, имя поля API моноширинным |
| по выбору | «По выбору · N» | выключено | флажок | то же + причина, почему по выбору: «зависит от области значений» (границы осей), «зависит от единиц метрики» (единицы осей, `units`, пороги), «атрибут виджета» (`view_mode`), «зависит от характера данных» (`missingdatafunc`) |
| никогда | «Никогда · N» | — | текст, без флажков | перечень человеческими словами: источники (роли и метрики), период, агрегация, подписи, замещения, связи, неизвестные поля, положение; это **не** недоступные флажки — чтобы читатель с экрана не искал, как их включить |

Правила:

- Зависимые поля (P1-06B §8, «сверить»): поле, которое не применяется при текущем значении управляющего поля (`fill` при `ds.N.type` = столбцы, `pointsize` при типе ≠ точки, `legend_*` при `legend` = 0, `*_color` при отсутствии пункта в `show`), **не включается** и перечисляется под группой с причиной `profiles.extract.dependent_excluded`. Включить его вручную нельзя: значение у виджета не наблюдаемо.
- `dataset_fields` берутся из **первого** набора `ds.0` (профиль применяет одинаковые значения ко всем наборам, P1-06B §8); если у наборов значения различаются, под группой — подпись «У наборов разные значения; взято из набора 1» с переключателем набора-источника.
- Палитра `series_palette` — цвета всех рядов в порядке наборов и элементов списка; набор-шаблон с `color_palette` даёт вариант «встроенная палитра Zabbix №{n}» вместо своей (одно из двух, P1-06B §8). Цвета ниже 3:1 к белому не блокируют (это цвета Zabbix), но помечаются в предпросмотре P1-06E (F5 P1-11F).
- Флажок «Включать значения, равные умолчанию Zabbix (профиль будет возвращать их)» — **включён**: профиль фиксирует полный вид, применение к другому виджету вернёт его поля к умолчанию, если у источника они по умолчанию. Выключен — в профиль попадают только отличающиеся значения (режим «только изменённое»; при применении остальные поля виджета-цели не трогаются). Если при включённом флажке ни одно поле класса «профиль» не отличается от умолчаний — предупреждение `profiles.extract.no_fields`, сохранить можно.
- `thresholds.N.*` (`item`) включаются только парой «порог + цвет» и только все вместе (один флажок «Пороги · N» в «По выбору»), с подписью единиц метрики, если она известна из каталога.
- Несколько выбранных виджетов: для каждого типа с `edit` источник — первый по порядку чтения; строка `profiles.extract.multi_source` с выбором другого источника того же типа; получается профиль с разделами по типам. Виджеты без `edit` в выборе перечисляются как пропущенные.

#### 8.2 Имя, описание, назначение

- Имя — обязательно; по умолчанию пустое (не имя виджета: имя виджета — текст про данные, не про оформление). Совпадение с существующим именем — предупреждение `profiles.name.taken`, не блокировка (имя не идентичность).
- Описание и теги — необязательны; теги — через запятую, без учёта регистра.
- Назначение: «Новый профиль» (по умолчанию) или «Раздел «{widget_type}» в существующий профиль» со списком профилей «мой» и «из файла» (встроенные и «Не проверено» в списке отсутствуют). Во втором случае раздел типа заменяется целиком, `version` растёт, остальные разделы не трогаются (`profiles.extract.target.replace_section`); так из графика и из значения собирается один профиль на два типа.

#### 8.3 Итог и сохранение

- Итог перед сохранением: «В профиль войдут N полей и палитра из M цветов; K полей «по выбору» не включены; L полей не входят в профиль никогда» (`profiles.extract.summary`). Числа пересчитываются при каждом переключении флажка.
- «Сохранить в библиотеку»: объект создаётся атомарно (временный файл → `fsync` → rename, O-018), получает `profile_id`, `version` = 1, `adapter` = версия адаптера черновика (7.4), диапазон совместимости — вычисленный. Результат — тост `profiles.extract.saved` с действиями «Показать в библиотеке» и «Применить к другим виджетам…» (открывает массовое применение P1-06G с этим профилем; в P2–P3 до P1-06G — без второй кнопки).
- Отмена — ничего не создаёт.

#### 8.4 Отказы

| Причина | Что видно | Сохранить |
|---|---|---|
| все поля класса «профиль» зависимы и исключены, палитры нет | список пуст, `profiles.extract.no_fields` | нет |
| имя пустое | ошибка у поля | нет |
| старый вид виджета в файле | только «Палитра рядов», подпись `profiles.extract.blocked.legacy_view` | да (профиль из одной палитры) |
| поле виджета с недопустимым значением (находка P1-04F `widget_field_invalid`) | поле в группе с ошибкой и снятым флажком; включить нельзя | да, без этого поля |
| хранилище недоступно (P1-09D) | `errors.storage.unavailable` | нет |

#### 8.5 Метка у источника

После сохранения включённые поля исходного виджета получают локальную метку происхождения «из профиля «{name}»» версии 1 (P1-06A §3.3): значения виджета не меняются, шаг истории не создаётся, в файл черновика ничего не пишется. Смысл — виджет-источник сразу участвует в «Обновить из профиля» и в счётчике использования. Об этом сказано в окне (`profiles.extract.marks_source`).

Метка — неотменяемая служебная операция (решение В-16, 26.10.2026): она не попадает в стек отмены ни в одном виде черновика. Локальный черновик — запись в `profile-marks.json` без шага `editor.op.*`. Рабочая копия — операция `apply_style_profile` с пустым списком изменений значений и признаком `service: true`: она записывается в список операций (O-018), но «Отмена» (P1-04G §4.1 «снимает последнюю операцию») такие операции пропускает, в «Мои изменения» они не показываются (нет изменений «база → черновик») и при публикации ничего не пишут. Снять метку можно только явным «Отвязать от профиля» (P1-06G §6.1), которое, напротив, является шагом истории (Q16).

### 9. «Создать заготовку» (14-05)

#### 9.1 Что берётся из виджета

| Что | В заготовку | Как показано |
|---|---|---|
| тип, имя | `widget_type`, имя по умолчанию = имя виджета (при вставке можно изменить) | заголовок, поле «Имя заготовки» = имя виджета |
| размер | `default_size` = текущие ширина × высота | подзаголовок |
| все поля не-ссылки (классы «профиль», «по выбору», «никогда» матрицы, кроме исключений ниже) | как есть, включая период `from/to`, агрегацию, фильтры проблем, подписи, цвета, `rf_rate`, `view_mode` | блок «Хранится» |
| поля-ссылки на узлы и элементы (типы 1–13 с ролью/метрикой, O-034) | **параметры** (§9.2) | таблица «Источники → параметры» |
| положение, `reference`, `*._reference`, `or.*`, маски и имена узлов, неизвестные поля, ID сервера, подключение | **никогда** | блок «Не хранится»; часть из них — препятствия (§9.3) |

#### 9.2 Источники → параметры (обязательная замена)

Каждое поле-ссылка получает параметр; имя параметра — поле ввода (`^[a-z][a-z0-9_-]{1,63}$`, как имя роли P1-05 дополнение §1), уникальное в заготовке.

| Источник в виджете | Параметр по умолчанию | Описание и свойства |
|---|---|---|
| роль черновика «{role}» (выбор `all` / `one` / `slot`) | `param` = имя роли; `cardinality` = роли; выбор `slot` → параметр с `cardinality: one` и подписью «слот «{slot}» роли» | описание роли |
| повторная ссылка на ту же роль в другом поле (`ds.1.hosts.0`) | **тот же параметр** (`blueprints.parameter.same`); объединение можно снять, тогда два параметра | — |
| метрика каталога «{metric}» | `param` = ключ метрики, нормализованный к правилу имени; `value_type`, `units` — из каталога; сам ключ, каталог и селектор в заготовке **не хранятся** (решение В-14): метрику выбирают заново при каждой вставке | имя метрики |
| ссылка «нужна привязка» (без роли/метрики, O-034) | параметр без типа значения и единиц, `blueprints.parameter.unbound_source` | пусто; при вставке предлагается любая метрика с предупреждением |
| рабочая копия: реальный узел по ID или имени | параметр-роль `many` без описания; имя по умолчанию `hosts`, `hosts_2`… | имя узла **не** попадает ни в имя, ни в описание параметра |
| рабочая копия: элемент данных по ID (`itemid.N`, `ds.N.itemids.M`) | параметр-метрика; тип значения и единицы — из локальных метаданных копии (I-4 P1-04H), если есть; иначе без них | ключ элемента не копируется в имя параметра автоматически, если содержит имя узла (сканер) |
| рабочая копия: шаблон имени элемента `ds.N.items.M` (например, `CPU*`) | параметр-метрика без типа; шаблон имени **не** сохраняется | — |
| `override_hostid` на роль | параметр-роль `one` | — |
| `override_hostid._reference` | препятствие §9.3 | — |

Имена параметров проверяются сразу (`blueprints.parameter.name_invalid`, `blueprints.parameter.name_taken`). Правило автоматики: **никакие источники не подбираются и не переименовываются молча**; всё, что сделано по умолчанию, видно в таблице.

#### 9.3 Препятствия (блокировки сохранения)

Каждое препятствие — отдельная строка с причиной и переключателем «решение / решение не выбрано»; пока хотя бы одно без решения, «Сохранить в библиотеку» недоступна и сводка `blueprints.save.blocked.summary` называет число. Решение действует только на заготовку, виджет в черновике не меняется. Ничего не отбрасывается без явного выбора.

| Препятствие | Поля | Причина (подпись) | Решение в окне |
|---|---|---|---|
| имя или маска узла в поле-ссылке | `ds.N.hosts.M` литералом (`pg-a-*`, видимое имя), `problemhosts.N`, `hostids.N` без роли | `blueprints.save.blocked.host_names` | «Заменить параметром-ролью» (создаёт параметр `many` без описания; литерал не сохраняется) |
| замещения по шаблонам имён | `or.N.*` | `blueprints.save.blocked.overrides` | «Сохранить без замещений (or.*)» |
| связь с другим виджетом | `time_period._reference`, `override_hostid._reference`, `ds.N.itemids.M._reference` | `blueprints.save.blocked.reference_link` | «Убрать связь: {field} — умолчание Zabbix» (период — умолчание Zabbix; переопределение узла — отсутствует; элемент по ссылке — удалить из набора, если набор станет пустым — набор удаляется с подписью) |
| неизвестные поля | `registry_state: unknown` | `blueprints.save.blocked.unknown_fields` + `_hint` | «Сохранить без неизвестных полей» |
| обязательное поле пусто (`item` без элемента, `svggraph` без наборов) | `itemid.N`, `ds.*` | находка P1-04F «неполная конфигурация» | нет решения: сначала настроить виджет; «Отмена» |
| тип без `create` | — | действие не показывается | — |

`reference` самого виджета не препятствие: он отбрасывается всегда и выдаётся заново при вставке (P1-01I) — сказано в блоке «Не хранится».

#### 9.4 Предупреждения (не блокируют)

- Сканер значений P1-07C по строковым полям заготовки (`data_set_label`, `description`, `units`, `lefty_static_units`, `problem_name`, имя): находка класса «имя узла сети» или «маска узлов» с уверенностью «точно» или «возможно» — `blueprints.create.scan_warning` у поля с переходом в инспектор; сохранение не блокируется, но при «Экспорт в файл…» сканер запускается снова (§4).
- Рядов больше, чем цветов в палитре, или дубли узлов — не относится к заготовке (источники — параметры).

#### 9.5 Сохранение и результат

- «Сохранить в библиотеку» — объект `zdashstitch.widget-blueprint/v1` с `blueprint_id`, `version` 1, `adapter` 7.4, диапазон совместимости — вычисленный по реестру для типа и полей; атомарно (O-018).
- Результат — тост `blueprints.create.saved` с «Показать в библиотеке»; вставка — через «Добавить виджет» → «Из заготовок» (P1-06F). Автоматической вставки или замены исходного виджета нет.
- Исходный виджет не получает меток: вставленные и исходный виджеты от заготовки не зависят.

### 10. Клавиатура, фокус, чтение с экрана

| Экран | Правила |
|---|---|
| Разделы библиотеки (14-01, 14-02) | подразделы — вертикальный список ссылок (не вкладки); фильтры — группы переключателей с именем группы («Тип виджета», «Происхождение»); список — сетка с заголовками колонок, стрелки по строкам, Enter — карточка, выбор ≠ фокус (P1-03H); сортировка — `common.a11y.sort_column`; плашки состояния — текст в ячейке, не только цвет; карточка — область с заголовком-именем; предпросмотр — `role="img"` с описанием «Предпросмотр профиля на синтетических данных: {список включённых полей}»; палитра — список цветов с текстовыми значениями |

## Проверки приёмки P1-06C–D

- Разделы «Профили оформления» и «Заготовки виджетов» работают без подключения; карточка показывает тип, версию, вычисленную совместимость, использование, происхождение «мой / встроенный / из файла», и никогда — ID сервера, узлы, элементы данных, подключение, имя пользователя.
- Встроенный профиль не меняется и не удаляется; «Дублировать» даёт изменяемую копию; удаление используемого профиля не блокируется и предупреждает, метки «из профиля» снимаются.
- Импорт файла профиля/заготовки идёт через «Импорт файлов» с явным выбором «Заменить (новая версия)» / «Сохранить как копию» при совпадении идентификатора; файл для другого адаптера сохраняется как «Не проверено» и не применяется; файл новее приложения и заготовка с масками/замещениями/связями/неизвестными полями отклоняются с кодом; пакет панели профили и заготовки не содержит.
- Экспорт — один файл на объект, без локальных сведений; экспорт заготовки проходит сканер значений; при неутверждённых форматах экспорт недоступен с «Появится позже».
- «Сохранить оформление как профиль» включает по умолчанию только класс «профиль», «по выбору» — выключено с причиной, «никогда» — только перечислено; зависимые поля исключаются с причиной; виджет не меняется, получает только локальную метку.
- «Создать заготовку» заменяет каждую ссылку на узлы и элементы параметром с видимым именем и свойствами; маски и имена узлов, `or.*`, `_reference`, неизвестные поля блокируют сохранение до явного решения; ничего не отбрасывается молча; строковые поля проходят сканер с предупреждением.
- Все экраны проходимы с клавиатуры; состояния не передаются только цветом; модальные окна возвращают фокус на виджет.

## Открытые вопросы владельцу

1. **Метка у источника профиля (§8.5):** после извлечения помечать исходный виджет «из профиля» версии 1 (рекомендация: да — виджет участвует в «Обновить из профиля» и в счётчике) или оставлять его без метки.
2. **Рабочая копия:** метка происхождения у источника — операцией `apply_style_profile` без изменения значений (рекомендация) или только для локальных черновиков.
3. **Встроенные объекты:** поставлять два эталонных профиля P1-06A §12 как «встроенные» (рекомендация: да, только профили; встроенных заготовок нет).
4. **Редактирование заготовки:** в MVP только имя/описание/дублирование/пересоздание из виджета (рекомендация) или полный редактор полей заготовки (расширяет P1-06E).
5. **Имя файла по умолчанию при экспорте:** `{slug}.style-profile.yaml` / `{slug}.widget-blueprint.yaml` (рекомендация; суффикс даёт распознавание до разбора и не мешает распознаванию по `format`).
6. **Флажок «Включать значения, равные умолчанию Zabbix»** включён по умолчанию (рекомендация: профиль — полный вид) или выключен («только изменённое»).
7. **Неизвестные поля в заготовке:** препятствие с явным решением «Сохранить без неизвестных полей» (рекомендация; P1-06A §4 говорил «не сохраняются», сводка там же — «блокировка») — подтвердить формулировку.
