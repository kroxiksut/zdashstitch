# Z80-P0-04 — контракт JSON-метрик

**Решение O-041, вариант 1.** Это контракт переносимых каталогов, а не подтверждение чтения или записи Zabbix 8.0. [Документация Zabbix 8.0](https://www.zabbix.com/documentation/8.0/en/manual/config/xml_export_import/templates) задаёт `JSON (6)` для `value_type` элемента и прототипа.

В разделе «Использование и граница импорта» зафиксировано состояние на момент P0-04. Локальный файловый профиль 8.0 появился на этапе Z80-P4-01. См. [контракт формата](../architecture/format_contract_v1_ru.md).

## Совместимость

- `zdashstitch.metrics/v1` и его схема неизменны: типы 0–5, без `json`. Читатель и писатель продолжают принимать и выдавать v1. Нельзя записывать объект с `json` под маркером v1 даже через Rust API.
- `zdashstitch.metrics/v2` имеет ту же структуру, пределы, семантику источника и диагностик, но дополнительно допускает `value_type: json`. Иных новых полей нет. Неизвестный тип отвергается; он не преобразуется в `text` и не пропускается.
- Новый нормализованный каталог без JSON может оставаться v1; с JSON обязан быть v2. Прочитанный v2, даже без JSON, записывается обратно как v2. Понижение версии не является побочным эффектом round-trip; явный экспорт в v1 возможен только после отдельной проверки отсутствия JSON и не добавляется этой задачей.
- Старый потребитель, знающий только v1, получает явный отказ по `format` каталога v2. Для старого потребителя нет безопасной автоматической замены JSON на text или удаления отдельной метрики.
- `project/v1` и `project/v2` ссылаются на `catalog_id` и путь, не кодируют версию каталога. Их схемы не меняются. В одном DATA-ONLY ZIP допустимы каталоги обеих версий; пакет принимается целиком или отвергается целиком, без пропуска неизвестного каталога. Каталог v2 с JSON может существовать в проекте без ссылки из виджета.

## Использование и граница импорта

- JSON — метаданные каталога. В Graph, Item value и переносимом поле Zabbix типа 4 ссылка на JSON блокируется до создания плана; `format=v2` не даёт capability. LLD-прототип JSON остаётся прототипом и требует найденного экземпляра; сопоставление типа 6 само по себе не разрешает публикацию. Значения элементов не загружаются.
- `template_import` 7.4 независимо сохраняет прежнюю ветку и строго отвергает `value_type=6`. Сырой экспорт с `zabbix_export.version: 8.0`, включая смешанные шаблоны, пока атомарно отвергается `template_export_version`: формат экспорта 8.0 и его полнота относятся к Z80-P4-01. В этой задаче проверяется смешанный **нормализованный** каталог v2 и пакет v1/v2; это не заявка на импорт сырых файлов 8.0.
- Существующий серверный `lookups` 7.4 отвергает весь item/prototype inventory, если в нём встречается `value_type=6`; обычные элементы того же ответа тогда не показываются. Версионное read-only чтение смешанного inventory 8.0 нужно выделить и испытать отдельно в Z80-P2/Z80-P4. Общий парсер 7.4 здесь не расширяется до 6, а серверный доступ 8.0 остаётся закрытым.
- Входной неизвестный формат/тип и любое несоответствие версии типу вызывают отказ без частично выданных каталогов. Метрики и диагностические признаки LLD сохраняются при допустимом v2 round-trip. Конкретная лабораторная 8.0 и её возможности остаются неподтверждёнными.
