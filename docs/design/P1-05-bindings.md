## P1-05A — намерение, источник и область

- Вход: из «Панели в Zabbix» («Заменить узел сети», «Клонировать») — сначала копия (P1-03), затем этот мастер; из раздела «Привязки» открытой копии; из «Структуры» с выбранными страницами или виджетами.
- Намерение выбирается явно: «Заменить узел сети» или «Клонировать панель».
- Область: «Вся панель» (по умолчанию, для клона — единственная), «Выбранные страницы», «Выбранные виджеты». Частичная область показывает предупреждение «Ссылки на {host} вне области останутся без изменений: {count}».
- Для замены узла выбирается заменяемый узел из найденных в панели (с числом ссылок на каждый). Базой служит снимок копии; локальные правки видны отдельно в «Публикации».

## P1-05B — зависимости источника

Инвентаризация (макет 09-01) группирует ссылки выбранного узла по страницам и виджетам. Колонки: виджет, тип, как ссылается, что будет.

| Как ссылается | Пример | Что будет при замене (O-003) |
|---|---|---|
| элемент данных по ID | `item`, явные элементы `svggraph` | изменится: элемент целевого узла с тем же `key_` |
| шаблон узла сети по имени | `svggraph` `ds.N.hosts.N` = видимое имя узла без `*` | изменится: имя целевого узла |
| маска узла (`*`) или шаблон элементов | `pg-a-*`, `CPU*` | замена: не меняется, «останется на старом»; клон: нужно решение (P1-05D) |
| график по ID | `graph` (classic) | изменится только после лабораторного контракта; до того — «не поддерживается» |
| узел сети в виджете неподдержанного типа | `tophosts`, `problems` | останется на старом узле; список подтверждается |
| связь между виджетами | `reference` | сохраняется; для клона — внутри копии |
| элемент данных LLD | `pgsql.db.size[proddb]` | нужен экземпляр на целевом узле (P1-05D) |
| неизвестная зависимость | неизвестный тип или поле | сохраняется как есть; если её надо менять — блокировка |

Состояния строки: поддерживается, частично (часть рядов виджета), не поддерживается (останется на старом), осиротевшая (виджет-получатель ссылки не попал в область). Счётчики сверху: «Изменятся», «Останется на старом», «Не найдено».

## P1-05C — целевые узлы сети

- Поиск по группе узлов сети, тегу и имени; группы и теги только помогают найти узлы, в соответствиях хранится выбранный упорядоченный список. Новые узлы группы сами не добавляются (P3-02B).
- Для каждого узла видно, сколько шаблонов источника на нём есть («2 из 2»); неполное совпадение — предупреждение «часть метрик не найдётся», а не отказ.
- Порядок задаёт слоты: 1-й источник → 1-я цель; лишние цели — «новый слот», лишние источники — «нет цели» (на шаге «Серии»). Порядок меняется кнопками «выше/ниже» (с текстовыми именами для чтения с экрана).
- **Набор узлов источника** (`bindings.source_set.*`) — группировка мастера клона: узлы, на которые ссылаются одни и те же виджеты (например, все узлы графиков PostgreSQL). Это не роль `project/v2`: у копии с сервера ролей нет (дополнение P1-05 §2; M-06), термин «роль» в мастере клона не используется. Слова Prod/Pilot/Test — только данные пользователя.
- Пустой список узлов — «Узлы не найдены или учётная запись их не видит» (P1-IN-08).
- Цели берутся из того же подключения, что и исходная панель; клон в другое подключение в MVP невозможен.
- Для замены узла шаг «Новый узел» — тот же экран (09-02) с одиночным выбором, без порядка слотов и без набора узлов источника.

## P1-05D — соответствия и ручное решение

Таблица (макет 09-03): источник → цель, совпадение, сколько виджетов зависит. Фильтры по статусу, «Принять точные (N)», клавиатура: стрелки по строкам, Enter — открыть кандидатов, пробел — отметить для массового действия.

| Совпадение (P1-IN-03) | Как показано | Что нужно |
|---|---|---|
| `exact` — тот же `key_`, тип значения и единицы | «Точно» | можно принять массово |
| `compatible` — ключ совпал, единицы или происхождение отличаются | «С отличиями» + что именно | просмотр; переходит в предупреждение публикации |
| `ambiguous` — шаблон имени даёт несколько кандидатов | «Неоднозначно» + число кандидатов | выбрать кандидата или «Оставить шаблон» |
| `missing` — ключа нет и он не из LLD | «Не найдено» | другой элемент вручную или оставить неразрешённым (блокирует публикацию) |
| `unresolved_lld` — экземпляра LLD нет на цели | «Не найдено (LLD)» + экземпляры того же прототипа (прототип читается `itemprototype.get` / `graphprototype.get` — только чтение, read allowlist P1-IN-08) | ручной выбор экземпляра (P3-02J) или неразрешённым |
| `denied` — не виден правами | «Не найдено или нет доступа» | то же, что `missing`; недоказанное «нет прав» не утверждается |

Боковая колонка кандидатов: ключ, тип, единицы, шаблон-источник; «Основания» — почему кандидат предложен. Похожее имя не считается доказательством.

Режим «метрика каталога → элемент на узле» на 09-03 используется не только для локального черновика (дополнение P1-05 §3.1), но и при вставке заготовки в копию с сервера (P1-06F §11): сначала выбирается метрика каталога библиотеки, затем элемент по её ключу на каждом узле. Плашки статусов этого режима получают ID `blueprints.insert.status.*` или общее пространство, выбранное при реализации (P1-06E–F, языковая проверка).

Решения клона (макет 09-04):

- **Маски узлов и шаблоны элементов** в графиках — обязательная строка на каждую: «Новый шаблон» с предпросмотром совпадений на цели (правила Zabbix 7.4: видимое имя, без учёта регистра, только `*`) или «Как есть» с предупреждением «копия покажет данные исходной области». Без решения — «Далее» недоступно.
- **Общие узлы** (Zabbix server, балансировщик): «Оставить исходный» — осознанный выбор, без предупреждения; ссылки не меняются.
- **Список «Останутся на исходных узлах»** — виджеты неподдержанных типов и строки «как есть»; обязательный флажок «Подтверждаю этот список».

Для замены узла тот же список (виджеты неподдержанных типов, маски) подтверждается в предварительных проверках публикации (P1-08C: «Подтвердить список»).

## P1-05E — итог преобразования

Замена узла: одна подтверждаемая замена старого узла во всех поддержанных ссылках области; остальные ряды, настройки, геометрия и доступ не меняются. Итог: изменятся (ссылки и виджеты), не меняются, останутся на старом (подтверждено), не решено (блокирует).

Клон (макет 09-06): новое имя (обязательно; уникальность проверяет сервер при записи), то же подключение, исходная панель не меняется, копируется вся структура (страницы, виджеты, связи виджетов, неизвестные поля). Блоки итога — те же, плюс «оставить исходный» и добавленные ряды. Владелец и доступ клона выбираются в «Публикации» (P1-08E/I): до лабораторного контракта P5-08 копия личная, затем доступ по выбору, по умолчанию — копия доступа исходной панели (O-031, решение 3 от 26.10.2026). Переход — «К публикации»; на этом шаге сервер не меняется.

## P1-05F — число узлов и серий

Редактор (макет 09-05) для каждого графика набора узлов источника: «было» (ряды источника) и «станет» (ряды копии по слотам), добавить/убрать/переставить узел.

- Новый ряд берёт метрику и настройки ряда-образца (тип, ось, агрегация); подпись — как у соседних рядов; цвет — следующий из палитры профиля, если виджет помечен «из профиля» и у профиля есть палитра (P1-06A §8); иначе — по детерминированному правилу P3-03B; в обоих случаях не совпадающий с соседними. Всё видно до принятия; предпросмотр легенды — синтетика с меткой (O-028).
- Для набора рядов «шаблон узла» узел добавляется в `ds.N.hosts`; для набора «список элементов» — элемент в `ds.N.itemids` (цвет нового элемента — после лабораторного контракта, P3-02C).
- Меньше целей, чем источников: лишний ряд удаляется; удаление показывается как изменение в «Публикации».
- Ограничения: дубль узла, метрика отсутствует на узле, несовместимые единицы или тип, лимит рядов — блокировка с причиной.
- Виджеты «один узел на виджет» (`item`, `graph` classic) при росте числа целей — блокировка «Для {host} нет своих виджетов» со ссылкой «Открыть редактор страницы» (P1-04/P4-03) или «уберите узел из целей». Мастер не создаёт виджеты и не меняет раскладку.

Обязательный пример: две серии PostgreSQL (pg-a-01, pg-a-02) → три узла (pg-b-01, pg-b-02, pg-b-03); третья серия получает ту же метрику и настройки.

## P1-05G — привязки и повторная проверка

Привязки рабочей копии (подключение, идентичность сервера, ID целевых узлов и элементов, порядок слотов, решения и основания) хранятся как операции копии (O-018); у локальных черновиков — в `local-bindings/v1` рядом с черновиком в хранилище приложения. В переносимые файлы и пакеты не попадают никогда.

| Событие | Затронутые привязки | Состояние |
|---|---|---|
| Другое подключение или идентичность сервера | все | «Недействительна» |
| Обновлена версия Zabbix | все | «Устарела», проверить |
| Изменились права учётной записи | все | «Устарела», проверить |
| Новый снимок («Скопировать заново») | строки затронутых виджетов | «Устарела» |
| Новая версия каталога метрик | строки этого каталога | «Устарела» |
| Целевой узел или элемент больше не виден | эта строка | «Недействительна: не найдено или нет доступа» |

Раздел «Привязки» вне мастера (макет 09-07): таблица «источник → цель», состояние, причина; «Проверить все»; для недействительной строки — «Выбрать другой», «Убрать слот»; автоматически другой узел не выбирается. «История привязок» — кто и когда выбрал соответствие. «Сбросить все привязки» — с подтверждением. Любое изменение привязок делает план публикации недействительным (P1-01C §6, причина `publication.plan.reason.bindings_changed`).

У копии с сервера в «Привязках» есть блок «Ссылки без привязки» (`bindings.unbound.*`): виджеты, вставленные из буфера (P1-04E) или из заготовок (P1-06F), чьи ссылки на узлы и элементы ещё не выбраны. Выбор — те же экраны 09-02/09-03 по виджету; для ссылки на элемент сначала выбирается метрика каталога библиотеки, затем элемент по её ключу (`blueprints.insert.resolve_copy(param, metric_ref, hosts[])`). Это не роли: роли у копии появляются только после «Сделать переносимой» (P1-07I). Пока в блоке есть строки, публикация блокируется находкой `source_binding_required` (P1-04F).

## P1-05H — handoff для P2-02/P2-03, P3-01/P3-02

| Команда | Предусловия | Успех | Ошибки (коды) |
|---|---|---|---|
| `bindings.inventory` | черновик, узел (замена) или набор узлов источника (клон) | ссылки по страницам/виджетам с видом и итогом | — |
| `bindings.targets.search` | подключение | узлы с группами и покрытием шаблонов | `not_connected` |
| `bindings.targets.set` | список узлов, порядок | слоты сохранены операцией | `duplicate_slot` |
| `bindings.resolve` | цели заданы | строки соответствий со статусами P1-IN-03 и основаниями | — |
| `bindings.decide` | строка | решение записано операцией (кандидат, экземпляр LLD, шаблон, как есть, оставить исходный) | `candidate_not_visible` |
| `bindings.confirm_kept` | список «останутся на исходных» | подтверждение записано | — |
| `bindings.cardinality.set` | график набора узлов источника | ряды по слотам | `duplicate_host`, `metric_missing`, `incompatible_units`, `series_limit`, `single_host_widget` |
| `bindings.recheck` | подключение | состояния строк | — |
| `bindings.reset` | подтверждение | привязки удалены, план недействителен | — |

Данные строки соответствия: `source_ref` (виджет, поле, узел, элемент), `target` (узел, элемент), `match` (`exact/compatible/ambiguous/missing/unresolved_lld/denied`), `applicability` (`editable/read_only/unsupported`), `evidence` (ключ, тип, единицы, шаблон-источник), `decision`, `state` (`checked/stale/invalid`), `checked_at`. Ответы содержат коды и параметры, не готовый текст.

Блокировки для «Публикации»: любая обязательная строка `ambiguous/missing/unresolved_lld/denied` без решения; маска или шаблон без решения (клон); неподтверждённый список «останутся на исходных»; виджет «один узел» при росте числа целей; устаревшие или недействительные привязки.

Доступность: шаги — ссылки в порядке табуляции; таблицы — сетка с заголовками; выбор кандидата — группа переключателей; итог проверки привязок объявляется live-region; порядок слотов меняется кнопками, не только перетаскиванием.
