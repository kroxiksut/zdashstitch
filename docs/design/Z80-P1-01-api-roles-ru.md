# Z80-P1-01 — API, авторизация, роли и доступ Zabbix 8.0

Дата сверки: 17.11.2026. Это вход для проектирования и последующих контрактных тестов, а не подтверждение поддержки 8.0. Точный patch и разрешённый лабораторный сервер 8.0 пока неизвестны. Наблюдения P1-IN-01/08/11 в [`backend_inputs_ru.md`](backend_inputs_ru.md) относятся только к лаборатории **7.4.16**; их коды ответов, объёмы видимости и успешные операции нельзя переносить на 8.0. Синтетические fixture Z80-P0-05 не содержат ролевых ответов. Серверный gate 8.0 остаётся закрытым.

Общее правило: `apiinfo.version` проверяется до передачи учётных данных; затем выбирается отдельный адаптер. Авторизация, разрешение метода ролью, видимость объекта и право на конкретное изменение — четыре разные проверки. Выбранный пользователем режим `read_only` запрещает запись даже с административным токеном. Положительный результат чтения правил роли или `dashboard.get` сам по себе не разрешает `dashboard.create/update`.

## Контракт по случаям

В таблице «8.0 документ» означает подтверждение официальной документацией ветки, **не** испытание установленного patch. «Лаб» — обязательное доказательство перед включением соответствующей серверной возможности. Все API ошибки классифицируются по структурированным полям JSON-RPC и стадии операции; точную английскую строку `data` нельзя считать стабильным контрактом, выводить как готовый пользовательский текст или сохранять с секретами.

## Следующие независимые проверки

1. **Z80-P2-01 (read/auth):** точный patch; mock и разрешённая 8.0 lab для version-before-credential, login/token/checkAuthentication, структурированных ошибок и read allowlist. Снять только санитарные коды/формы ответов, не токены и не raw корпоративные объекты. Отдельно проверить новые и обновлённые роли либо честно обозначить недоступный вариант.
2. **Z80-P2-02/03 и Z80-P3-01:** чтение snapshot и зависимостей при ограниченной видимости, owner/access как неполное evidence; не подменять отсутствие объекта доказательством отсутствия права. При изменении identity, role или видимости инвалидировать план.
3. **Z80-P5-03:** контрактный тест каждой операции записи на разрешённой тестовой панели и account: effective API method + dashboard action/object permission, неизменённые права и страницы, единственная отправка, read-back и неизвестный исход. `role.get current` рассмотреть как более узкий способ чтения собственной роли, затем принять версионный permission gate. 7.4.16 gate не расширять по номеру ветки.

Лабораторные тесты потребуют синтетические временные роли, пользователей, группы и панели с явным cleanup; полезные тестовые данные сохраняются по правилам AGENTS. Production и существующие шаблоны не использовать. Результаты должны содержать exact patch, способ установки/обновления и роль, иначе матрица 8.0 остаётся открытой. Для новых пользовательских состояний/текстов — Z80-P1-03 и общие `lang/en`, `lang/ru`, без готовой прозы из backend.
