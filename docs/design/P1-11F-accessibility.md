# P1-11F — доступность и платформы (проход G1a)

Статус: проход G1a принят владельцем 25.10.2026 (решения D1—D7 по рекомендации P1-11H). Версия: G1a v1, 25.10.2026. Область: экраны сценариев P2–P3 — «Начало», «Черновики», «Панели в Zabbix» и копирование, «Подключения», «Привязки» (замена узла, клон), «Публикация», «Настройки → Внешний вид / Общие / О программе».

Основа: чек-лист P1-00G §12, WCAG 2.2 AA, решения P1-00B/C/E, спецификации P1-02H, P1-03H, P1-05H, P1-08H (клавиатура и live-region), реализованные токены P2-00B (`ui/src/tokens.css`) и компоненты P2-00C.

## 1. Что можно проверить сейчас, а что — только в работающем приложении

Интерактивных прототипов нет: дизайн принимается по статичным SVG и спецификациям. Поэтому проход разделён:

| Проверка (P1-00G §12) | Сейчас (статично) | В работающем приложении |
|---|---|---|
| Всё доступно с клавиатуры; порядок табуляции и модель составных элементов | описаны в handoff P1-02H, P1-03H, P1-05H, P1-08H: шаги — ссылки в порядке табуляции, таблицы — сетка со стрелками, выбор — группы переключателей, диалоги — ловушка фокуса и возврат | проход клавиатурой каждого экрана — приёмка задачи экрана (§4) |
| Перетаскивание имеет альтернативу | везде, где есть ручка перетаскивания, нарисованы кнопки «выше/ниже» (08-01, 08-02, 09-02, 09-05) | проверка в P4 (холст) и P3-02E |
| Landmarks, заголовки, имена и описания | у значков-кнопок в макетах есть `<title>`; заголовок экрана один; навигации подписаны | инспекция дерева доступности |
| Ошибки, загрузка, конфликт, неизвестный итог объявляются без кражи фокуса | live-region описаны в handoff; ассертивно — только блокировка, конфликт, неизвестный итог | экранный диктор |
| Цели не меньше 32×32 | кнопки 32–42 px; см. замечание о значках-кнопках (§3) | замер в браузере |
| 200 % и 400 % / 320 CSS px | правила компактного окна 1024×720 и перекладки — P1-01B, P1-00B | проверка плотных экранов (11-04, 09-03, 03-01) |
| Уменьшение движения, принудительные цвета | в G1a анимаций нет (motion — P1-10, G1b); принудительные цвета реализованы в P2-00B | Windows High Contrast, контраст Linux |
| Светлая, тёмная, системная тема | токены P2-00B, автотест контраста основных пар | проверка на экранах |
| Длинный текст EN/RU, системные шрифты, 200 % | стресс-набор P1-00F §5 | Windows 10/11 и Ubuntu GNOME |

## 2. Статичные результаты

**Контраст.** Проверочная палитра макетов (MOCKUP_GUIDE) — по WCAG:

| Пара | Контраст | Итог |
|---|---|---|
| основной текст `#17213a` на `#ffffff` / `#f5f7fb` | 15,97 / 14,89 | AA |
| вторичный текст `#667085` на `#ffffff` / `#f5f7fb` / `#f8fafc` | 4,97 / 4,64 / 4,75 | AA (на грани) |
| акцент и основная кнопка `#3156a3` ↔ `#ffffff` | 7,02 | AA |
| выбранное `#1d3f86` на `#eef4ff` | 9,02 | AA |
| успех, внимание, ошибка, нейтральная плашка | 6,14 / 6,26 / 6,60 / 9,49 | AA |
| рамка поля и флажка `#98a2b3` на `#ffffff` | **2,58** | **ниже 3:1 (WCAG 1.4.11)** |
| недоступное `#98a2b3` на `#f2f4f7` | 2,34 | исключение WCAG для недоступных элементов |

Реализованные токены не повторяют эту ошибку: `--border-default` `#7a8d9b` на белом — 3,44. Палитра макетов — не токены реализации (MOCKUP_GUIDE), поэтому это замечание к макетам, а не к продукту.

**Смысл не только цветом.** Состояния везде дублируются значком и словом: плашки состояния черновика, маркеры сравнения (P1-08B), статусы проверок (P1-08C), совпадения (P1-05D), шаги мастеров (значок пройденного шага). Нарушений не найдено.

**Подписи и ошибки.** Поля форм подписаны над полем; ошибки формулируются рядом с полем и в сводке (P1-02, P1-09B). Технические сведения отделены от основного текста ошибки.

**Платформы.** Целевые — Windows 10+ и Linux с графической средой (Ubuntu 26.04 GNOME и WSL проверены в P1-IN-01/09); шрифты системные; нативный диалог файлов — ручная приёмка P2-07E; macOS в MVP не добавляется.

## 4. Предложение по приёмке (решение владельца)

Требование P1-11 «Windows/Linux и accessibility пройдены» до G1a буквально невыполнимо: экранов P2–P3 ещё нет, а прототипов проект не делает. Предлагается:

1. G1a принимается по статичному проходу этого документа.
2. Проверки §1 в правом столбце становятся **обязательным критерием приёмки каждой задачи экрана**: P2-01G (подключения), P2-05D (копирование), P2-03D (предпросмотр замены), P2-04 (публикация), P3-01C (клон), P3-02E (мастер соответствий), P2-00E экран настроек. Задача экрана не закрывается без записанных наблюдений «браузер / ОС / вспомогательная технология», и непроверенное сочетание не называется поддерживаемым (P1-00G §12, последний пункт).
3. Блокирующая находка доступности в задаче экрана возвращается в дизайн как дефект P1-11H, а не исправляется разработчиком на своё усмотрение.

**Изменение 28.10.2026 (решение владельца O-039).** Ручная проверка экранным диктором из критерия задач экранов исключена: владелец проверил клавиатуру и масштаб 200 %/400 % на Windows, Экранный диктор Windows признан непригодным для проверки, дальнейшие ручные проходы диктором не проводятся. Разметка для дикторов (ориентиры, имена, live-region) остаётся обязательной и проверяется автоматически; в README сказано, что с диктором интерфейс не проверялся, эталон — NVDA (Windows) и Orca (Linux), вклады через PR. Высокая контрастность проверяется встроенной темой `high_contrast` (O-038), а не только режимом ОС.

## Проверки приёмки

- Все пункты P1-00G §12 имеют место проверки: статично сейчас или критерием задачи экрана.
- Контраст текста и состояний в макетах — AA; найденные отклонения перечислены с предложением.
- Ни один статус не передаётся только цветом.
- Решение владельца по §4 записано до закрытия G1a.
