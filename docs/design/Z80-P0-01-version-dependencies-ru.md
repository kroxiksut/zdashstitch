# Z80-P0-01 — карта продуктивных зависимостей от Zabbix 7.4

**Срез:** 17.11.2026, текущие файлы рабочего дерева, включая незакоммиченные изменения. Это инвентаризация, не включение 8.0. Приоритет 8.0 задан ADR-011 и локальным планом; точный patch и лабораторные контракты 8.0 неизвестны. Под продуктивным вызовом ниже понимается код, достижимый из приложения, в отличие от `#[cfg(test)]`, demo и fixture.

## Владение версионным контекстом

| Контекст | Текущий источник и поток | Владелец после разделения |

## Тесты, demo, fixture и исторические ссылки

`v7_4()` и `7.4.16` внутри `#[cfg(test)]` модулей (`widget_capabilities.rs:541+`, `compatibility.rs:401+`, `portable_conversion.rs:731+`, `offline_pages.rs:993+`, многочисленные `tests/`) — регрессия и доказательства только 7.4. `ui/src/demo/*` и memory fixture `ui/src/lib/publication/client.ts:197-248` показывают синтетический 7.4.16, не являются runtime server selection; перед демонстрацией 8.0 им нужен отдельный fixture. `docs/history/`, примеры и ссылка на 7.4 в `docs/MVP_TRACEABILITY.md:9-28` не являются productive call sites. В матрице есть устаревшая формулировка «7.4 — единственный адаптер MVP»; до изменения нормативного текста сверить с ADR-011 и `docs/DOC_GOVERNANCE.md`, не трактовать её как разрешение включить 8.0 без контрактов.

## Порядок замены и приёмочные проверки

1. Z80-P0-02: server version → adapter registry и отдельный widget codec; 7.4 регрессия, 8.0, unsupported и prerelease. Все неизвестные write возможности закрыты.
2. Z80-P0-03: snapshot adapter identity, raw/canonical fingerprint, workcopy/base/advance и clone state; round-trip и restart прежних 7.4 файлов, новый 8.0 ID, отрицательный cross-version reopen без записи или порчи.
3. Z80-P4-01/02/03 и Z80-P3-01: различить export format, автономный профиль проекта и подключённый target; проверить переносимый пакет, redaction и mapping отдельно.
4. Z80-P2/P5: fixture и lab contracts exact patch для чтения, прав и каждой операции; только после них открывать соответствующий `VerifiedPlan` и отправитель.

Карта не меняет публичные схемы, безопасность или поддержку. Решение потребуется, если существующий формат хранения не позволит однозначно сохранить adapter identity для 8.0 либо понадобится изменить fingerprint/migration; фиксировать альтернативы в `OPEN_DECISIONS.md` до реализации.
