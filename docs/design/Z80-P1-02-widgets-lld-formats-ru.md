# Z80-P1-02 — входы по виджетам, LLD и форматам Zabbix 8.0

17.11.2026. Дополнение к P1-IN-02/04/05/10 из [backend_inputs_ru.md](backend_inputs_ru.md), относящимся к лаборатории **7.4.16**. Это сверка документации и текущего кода, а не реализованный адаптер или лабораторная приёмка 8.0. Точный patch целевого сервера пока неизвестен. Исторические результаты 7.4 сохраняются только для 7.4; пометка `[x]` у прежних P1-IN не подтверждает 8.0. «Документировано» ниже означает наличие контракта в официальном справочнике 8.0, а не разрешение capability `read/edit/create` в ZDashstitch.

Документация widget fields прямо предупреждает, что содержимое `fields` не валидируется при `dashboard.create`/`dashboard.update`; следовательно, успешный API ответ не доказывает работоспособный виджет или сохранность связей. Требуются повторное чтение, сравнение структуры и проверка отображения на разрешённой лабораторной панели. [Пример справочника](https://www.zabbix.com/documentation/8.0/en/manual/api/reference/dashboard/widget_fields/scatter_plot).

## Обновлённые входы P1-IN

- **P1-IN-02:** повторить агрегаты snapshot на точном 8.0 patch: частоты всех типов, коды `fields.type`, новые имена, неизвестные расширения, длины/плотность, host/item/graph/reference и LLD ссылки. Реальные рабочие панели остаются за отдельным разрешением владельца. Синтетика не задаёт частоты.
- **P1-IN-04:** составить по каждой операции и типу отдельные read/preview/edit/create/append/copy результаты на временной лабораторной глобальной панели. Для `svggraph` включить серии, маски, item tags и `invert_values`/`show_hostnames`; для `piechart`, `topitems`, `geomap`, `scatterplot` — новые поля. Проверять page/widget IDs, defaults, внутренние reference, незатронутые поля и read-back. Не распространять контракт 7.4.16 на 8.0.
- **P1-IN-05:** получить разрешённые 8.0 экспорты стандартных и клонированных пользовательских шаблонов в YAML/JSON/XML, включая JSON item/prototype и LLD, плюс отдельный экспорт глобальной панели. Зафиксировать версии, размеры, состав, пределы и ошибки; секреты/названия не переносить в repo. Проверить UTF-8, опасные XML-конструкции, непрозрачные поля и различие template/global dashboard. Текущий parser отвергает `version: 8.0`, и это корректное fail-closed поведение до реализации.
- **P1-IN-10:** оставить историческую 7.4.16 таблицу без переименования. Для 8.0 завести отдельные version-bound записи типов/полей и capability по каждой операции; 33 документированных типа в API object (32 прежних плюс `scatterplot`) — это перечень для инвентаризации, не 33 реализованных widget codec. Не считать отсутствие поля в fixture доказательством его отсутствия на сервере.

## Неподдержанное и лабораторные пробелы

Сейчас серверный профиль 8.0 возвращает `UnsupportedVersion`; реестр 8.0 пуст. Нет подтверждённого серверного чтения/редактирования/создания/копирования ни одного 8.0 виджета, safe handling новых полей, импорта экспорта 8.0 или серверного mixed JSON/LLD inventory. Raw preservation в синтетическом тесте Z80-P0-05 не разрешает publish. Текущий `dashboard_write_allowlist` ограничен `dashboard.update` и `dashboard.create`; `configuration.import` в нём отсутствует.

Необходимы точный patch и роль лабораторного сервера, 8.0 `dashboard.get`/`configuration.export` с разными правами, полные YAML/JSON/XML, item/prototype/discovered случаи и проверка потерь при безопасном copy/update. Отдельно проверить отсутствие ссылки на скрытые правами объекты, inter-widget reference, default fields и полную перезапись при `configuration.import` только если владелец примет этот путь; сейчас он закрыт. Сравнение штатного экспорта глобальной панели с `project/v2` требует явного преобразования, не переименования формата.

Сверка локального состояния: `crates/zabbix/src/capabilities.rs` закрывает server 8.0; `crates/zabbix/src/widget_capabilities.rs` содержит доказанный реестр 7.4 и пустой 8.0; `crates/template_import/src/lib.rs` требует `EXPORT_VERSION = "7.4"`; `crates/zabbix/src/gateway.rs` задаёт read и dashboard-only write allowlists. XERJ запросы `WidgetCapabilityRegistry v7_4 svggraph`, `configuration.import allowlist dashboard`, `LLD widget fields graph item tags` сверены с `rg` и текущими файлами. `tools/xerj-local.ps1 status` не прочёл `xerj.exe` из-за ACL; локальный MCP `xerj_map` и `xerj_search` работали. Ни один XERJ запрос не использовал rerank.
