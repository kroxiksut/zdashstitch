## P1-06E — редактор и предпросмотр профиля

### 1. Точки входа и маршрут

| Откуда | Куда | Условие |
|---|---|---|
| карточка профиля (14-01) → «Изменить профиль» (`profiles.action.edit`) | редактор профиля, маршрут `/library/profiles/:profile_id/edit`, хлебные крошки «Библиотека / Профили оформления / {name}» | состояние `ok` или `invalid`; происхождение «мой» или «из файла» |
| «Библиотека» → «Создать профиль» (`profiles.action.new`) | редактор с пустым профилем: сначала окно «Для каких типов виджетов нужен профиль?» (разделы «График», «Значение элемента данных», оба) и «На основе встроенного «{name}»» (= дублирование, P1-06C §4) | — |
| карточка встроенного профиля → «Изменить профиль» недоступна (`profiles.origin.builtin_hint`); «Дублировать» → редактор копии | — | встроенный |
| карточка «Не проверено» (`unknown`) | редактор не открывается: подпись `profiles.state.unknown_adapter_hint` (поля чужого адаптера не выдумываются, P1-06C §6) | `unknown` |
| инспектор виджета → подпись «из профиля «{profile}»» → ссылка на карточку → «Изменить профиль» | — | профиль не удалён |
| тост «Сохранить оформление как профиль» (14-04) → «Показать в библиотеке» → «Изменить профиль» | — | — |

Редактор — отдельный экран раздела «Библиотека», не модальное окно: у него три колонки и предпросмотр, как у инспектора P1-04D с мини-холстом (12-03). Подключение не требуется. Редактор не касается черновиков: он меняет только объект библиотеки (P1-06A §3).

Окно 1024×720 (P1-01B): левая колонка сворачивается в выпадающий список разделов над полями, предпросмотр уходит под поля; порядок табуляции не меняется.

### 3. Поля раздела

Для каждого типа редактор берёт описание формы P1-04D (`editor.form.describe` точной версии адаптера) и показывает **только поля классов «профиль» и «по выбору»** матрицы P1-06B §8–§10 в порядке разделов инспектора: «Отображение» (ряды, легенда — `svggraph`; что показывать, значение, описание и единицы, время и индикатор, спарклайн — `item`), «Оси и пороги», «Дополнительно» (`show_problems` и зависимые), «Основное» (`view_mode`). Поля класса «никогда» не показываются и не упоминаются по именам — только перечень человеческими словами (`profiles.editor.never`), как в 14-04.

Строка поля: флажок «в профиле» (`profiles.editor.field.include`), человеческое имя (ID подписи из описания формы), элемент управления (тот же, что в инспекторе: список, число, флажок, цвет, текст), плашка класса «по выбору» с краткой причиной (`profiles.extract.why.*`), имя поля API моноширинным справа (как 14-04; в реализации — в «Технических сведениях» и подсказке, правило P1-04D).

| Правило | Как |
|---|---|
| Включение | флажок снят — поле не хранится в профиле и у виджетов при применении не меняется; снят по умолчанию для класса «по выбору» (O-012 п. 3) и для полей, которых не было в профиле; включён для полей, которые уже в профиле |
| Значение | редактируется только при включённом флажке; снятие флажка не стирает значение до сохранения (можно включить обратно); при сохранении невключённые поля не записываются |
| Умолчание Zabbix | включённое поле со значением, равным умолчанию, **хранится** в профиле (профиль возвращает умолчание — семантика «Включать значения, равные умолчанию» P1-06D §8.1); кодек при применении снимает поле у виджета (P1-06A §3.1) |
| Наборы `ds.N.*` | одна строка на поле, подпись `profiles.editor.applies_all_datasets`: значение применяется ко всем наборам одинаково (P1-06B §8) |
| Зависимые поля | если управляющее поле включено в профиль и его значение исключает зависимое (`ds.N.fill` и `ds.N.width` при виде ряда «столбцы», `ds.N.pointsize` при виде ≠ «точки», `legend_*` при `legend` = нет, `*_color`/`*_size` при пункте вне «Что показывать», `graph_item_problems` при `show_problems` = нет, `lefty_*` при `lefty` = нет) — строка недоступна с причиной `profiles.editor.field.dependent_hint` и не хранится; если управляющее поле **не** включено — зависимое можно включить, подпись `profiles.editor.field.dependent_on_widget` (применится, только если значение у виджета это допускает; иначе `partial` при применении, P1-06B §7) |
| Палитра рядов (`svggraph`) | блок «Палитра рядов»: цвета в порядке рядов, добавить/убрать/переставить (кнопки «выше/ниже» с текстом для чтения с экрана), шестнадцатеричный формат; альтернатива — «Встроенная палитра Zabbix №{n}» (`color_palette`), одно из двух (`profiles.editor.palette.exclusive`); пустая палитра допустима (профиль без цветов), тогда правило нового ряда — P3-03B |
| Контраст цветов (F5 P1-11F) | цвет с контрастом ниже 3:1 к белому — предупреждение у цвета и в итоге (`profiles.editor.palette.low_contrast*`); не блокирует (это цвета Zabbix, пользователь может работать на тёмной теме Zabbix) |
| Пороги (`item`) | один флажок «Пороги · N» класса «по выбору», внутри — пары «порог → цвет» с добавлением и удалением; подпись единиц `profiles.editor.thresholds.units_hint` (единицы запоминаются в профиле как справка для предупреждения `profiles.compatibility.reason.units_differ`; хранятся как `thresholds_units` в разделе `item` эскиза — вопрос 3) |
| `show.N` (`item`) | обязательное поле Zabbix: раздел `item` всегда хранит `show`; пустой список — ошибка `profiles.editor.field.show_required` |
| Раздел без полей | раздел без включённых полей и без палитры — ошибка `profiles.editor.section.empty`; профиль без разделов — `profiles.editor.no_sections` |
| Убрать раздел | «Убрать раздел «{widget_type}»» — без подтверждения (P1-00E §9: действие обратимо, ничего не теряется до сохранения): раздел скрывается, под списком разделов появляется строка `profiles.editor.section.removed` с «Вернуть раздел» (`profiles.editor.section.restore`); действует только при сохранении, Esc/«Отмена» возвращает всё |
| Неизвестное поле профиля (`invalid` из файла) | строка с текстом значения и ошибкой `profiles.field.unknown_for_type`, действие «Убрать поле {field}» (`profiles.editor.field.remove_unknown`); включить нельзя |

Источники, время, агрегация, фильтры, тексты, связи, геометрия, `rf_rate`, неизвестные поля виджетов — в редакторе отсутствуют (P1-06A §2). Профиль никогда не меняет тип виджета: раздел — ключ по типу.

### 4. Проверка и сохранение

| Проверка | Где | Текст |
|---|---|---|
| диапазон числа, формат интервала, формат цвета (`^[0-9A-F]{6}$`), допустимые значения списка — по описанию формы | у поля, сразу после ввода; сводка в заголовке раздела (`profiles.editor.errors_count`) и в правой колонке | `profiles.field.invalid` у поля с уточнением (`profiles.editor.field.range`, `profiles.editor.field.colour_format`, `editor.field.invalid_interval`) |
| минимум оси меньше максимума, если включены оба | у второго поля | `profiles.editor.field.axis_order` |
| порог без значения или без цвета | у пары | `profiles.editor.thresholds.pair` |
| `show` пуст | у поля | `profiles.editor.field.show_required` |
| своя палитра и встроенная одновременно | у палитры | `profiles.editor.palette.exclusive` |
| раздел пуст / разделов нет | заголовок раздела / левая колонка | `profiles.editor.section.empty` / `profiles.editor.no_sections` |
| имя пустое | у поля | `profiles.name.required`; совпадение — предупреждение `profiles.name.taken` |
| поле неизвестно адаптеру | у поля | `profiles.field.unknown_for_type` |

Правила сохранения:

- «Сохранить» (Ctrl+S) недоступна, пока есть хотя бы одна ошибка; причина — `profiles.editor.save.blocked` в правой колонке и в `aria-describedby` кнопки (14-07). Профиль с ошибками в библиотеку **не записывается**: состояние `invalid` возникает только при импорте файла (P1-06C §5) и исправляется здесь.
- Сохранение — атомарная запись объекта (O-018), `version` + 1 (новый профиль — 1), `adapter` — текущий (7.4), диапазон совместимости пересчитывается по включённым полям (O-029); локальная карточка получает «Изменено {time}». Дублирование и переименование версию не меняют (P1-06C §4).
- После сохранения — тост `profiles.editor.saved`; плашка «Не сохранено» снимается; редактор остаётся открытым. Черновики не меняются: у виджетов «из профиля» прежней версии появляется `profiles.field.origin.outdated` (P1-06A §3.2); об этом сказано до сохранения (`profiles.editor.save.outdated_hint`, 14-06).
- Автосохранения нет: версия — явное действие пользователя (отличие от черновика, P1-04G).
- Ошибка записи — `errors.storage.unavailable`, «Повторить»; изменения остаются в редакторе.

### 5. Предпросмотр на синтетике

Предпросмотр использует генератор P1-04I (`application`) с теми же правилами диапазонов, детерминированностью и метками, но вместо виджета черновика — **встроенный пример виджета** раздела: описание виджета с фиктивными метриками выбранного примера. Пользователь выбирает пример из списка (`profiles.editor.preview.sample.*`): для «Графика» — «3 ряда · байты (B) · 1 час» (по умолчанию), «2 ряда · проценты (%) · 1 час», «2 ряда · без единиц · 1 час»; для «Значения элемента данных» — «число с плавающей точкой · %» (по умолчанию), «целое · байты (B)», «текст». Зерно — от идентификатора примера и номера ряда (не от профиля), чтобы изменение полей не перерисовывало кривые.

| Правило | Как |
|---|---|
| Что показывает | только включённые поля профиля поверх умолчаний Zabbix; невключённые — как умолчание; подпись `profiles.card.preview`, метка «Синтетика» (`draft.preview.synthetic.badge`), пояснение `profiles.preview.hint` |
| Пороги и границы осей | пример с подходящими единицами показывает порог/границы; с другими единицами — порог не рисуется, подпись `profiles.compatibility.reason.units_differ` под предпросмотром (так виден смысл «по выбору») |
| Недопустимое значение | предпросмотр строится по ближайшему допустимому значению с подписью `profiles.editor.preview.invalid_hint` (14-07) — чтобы ошибка не ломала картинку |
| Тема | поверхность предпросмотра — фиксированные цвета светлой темы Zabbix 7.4 (белый фон виджета), **не** токены темы приложения: профиль хранит цвета Zabbix, тёмная тема ZDashstitch их не меняет (P1-09B, `profiles.hint.not_theme`); подпись `profiles.editor.preview.theme_hint`. Проверка приёмки: в тёмной теме приложения предпросмотр выглядит так же, как в светлой |
| Обновление | после каждого изменения поля, с задержкой 300 мс; ленивое, только для открытого раздела |
| Куда не попадает | ни в файл профиля, ни в карточку, ни в журналы (P1-04I); карточка библиотеки показывает ту же картинку в уменьшенном виде (P1-06C §3) |
| Чтение с экрана | `role="img"` с описанием `profiles.editor.a11y.preview` (список включённых полей и значений) |

### 6. Состояния редактора

| Состояние | Что видно | Действия |
|---|---|---|
| Загрузка описания формы | скелет полей, предпросмотр пуст; > 1 с — `common.state.loading` | — |
| Без изменений | плашки «Не сохранено» нет; «Сохранить» недоступна с подписью «нет изменений» (`profiles.editor.no_changes`) | Отмена = закрыть |
| Есть изменения | плашка `profiles.editor.unsaved`; подзаголовок «Версия {version} → {next} при сохранении» | Сохранить, Отмена → диалог |
| Есть ошибки | счётчик ошибок в заголовке раздела и в сводке; «Сохранить» недоступна с причиной; разделы с ошибками помечены в левой колонке (текст, не только цвет) | исправить, «Убрать поле» |
| Закрытие с изменениями (Esc, «Отмена», крошки, закрытие вкладки) | диалог `profiles.editor.close.dirty.*`: «Сохранить» (недоступно при ошибках, с причиной) / «Не сохранять» / «Отмена» — единственное подтверждение редактора: здесь теряются несохранённые изменения (P1-00E §9) | — |
| Встроенный профиль | открывается только для просмотра: все поля недоступны, баннер `profiles.origin.builtin_hint`, единственная основная кнопка «Дублировать для изменения» (`profiles.editor.action.duplicate_to_edit`) | дублировать → редактор копии |
| `invalid` (из файла) | баннер `profiles.editor.invalid_banner` с числом полей; поля с ошибками отмечены; сохранить можно после исправления | — |
| `unknown` (другой адаптер) | редактор не открывается (§1) | — |
| Профиль удалён в другой вкладке | баннер `profiles.editor.deleted_elsewhere`; «Сохранить как новый» создаёт объект с новым `profile_id` | — |
| Хранилище недоступно | `errors.storage.unavailable`, «Повторить» | — |
| Создание с нуля | все поля сняты, значения — умолчания Zabbix; палитра пуста; имя пустое; подзаголовок `profiles.editor.subtitle.new` | — |

Двух вкладок, правящих один профиль, правило P1-01C §3 не касается (профиль — не черновик): последнее сохранение побеждает, а редактор с устаревшей версией при сохранении получает `version_conflict` и предлагает «Сохранить как новый профиль» или «Перезагрузить» (`profiles.editor.version_conflict`).

### 7. Клавиатура и чтение с экрана

| Элемент | Правила |
|---|---|

## P1-06F — создание и применение WidgetBlueprint (вставка)

«Создание» заготовки — только из виджета (P1-06D §9, 14-05); здесь — применение: вставка на страницу.

### 8. Точки входа

| Откуда | Куда | Условие |
|---|---|---|
| редактор → «Добавить виджет» (P1-04C, 12-02) → группа «Из заготовок» (`editor.chooser.group.blueprints`) | шаг 1: список заготовок в группе; шаг 2: «Параметры» (14-08 / 14-09) | библиотека доступна; группа пуста — `blueprints.insert.empty` |
| карточка заготовки (14-02) | только подсказка «вставляется через «Добавить виджет» → «Из заготовок»» (`blueprints.create_from_editor`) — вставка из библиотеки невозможна, потому что нужна страница | — |
| тост «Создать заготовку» (14-05) | «Показать в библиотеке»; вставки нет (P1-06D §9.5) | — |

Подпись «Появится позже» у группы «Из заготовок» в 12-02 снимается (см. «Что изменится в принятых документах»).

### 9. Шаг 1 — выбор заготовки в окне «Добавить виджет»

Группа «Из заготовок» в 12-02 получает список строк: имя заготовки, тип (`widget.type.<id>` + код), «N ролей · M метрик» (`blueprints.params.summary`), размер по умолчанию, версия; поиск окна ищет и по именам заготовок. Правая колонка окна показывает карточку выбранной заготовки: параметры (как 14-02), «Не хранит», требуемая совместимость (`profiles.card.computed_range`), предупреждение `blueprints.insert.compat_warning`, если заявленная совместимость панели у́же. Кнопка «Добавить» заменяется на «Далее: параметры» (`common.action.next_step` с `step` = `blueprints.insert.step.params`; отдельного ID кнопки нет).

| Состояние заготовки (P1-06C §6) | В списке | Выбрать |
|---|---|---|
| `ok` | обычная строка | да |
| `unknown` (другой адаптер) | плашка «Не проверено» (`profiles.state.unknown_adapter`), причина `profiles.state.unknown_adapter_hint` | нет |
| тип без флага `create` в реестре точной версии | строка с причиной `blueprints.insert.reason.create_unsupported` | нет |
| объект не читается | `library.state.unavailable` + `blueprints.insert.reason.unreadable` | нет |

Заготовки в MVP — только `svggraph` и `item` (O-012). Реестр P0-09 — единственный источник права на создание (`capability_not_verified` иначе).

### 10. Шаг 2 — параметры (14-08)

Для каждого параметра заготовки (P1-06A §5, P1-06D §9.2) — карточка: имя параметра моноширинным, вид (`blueprints.parameter.role` / `blueprints.parameter.metric` с кардинальностью, типом значения и единицами), описание из заготовки, состояние (решено / `bindings.clone.pattern.undecided`).

#### 10.1 Параметр-роль (локальный черновик)

| Элемент | Правило |
|---|---|
| Список ролей черновика | только роли с совместимой кардинальностью: параметр `many` — любая роль (выбор `all`); параметр `one` — роль `one` (выбор `one`) или слот любой роли (`blueprints.insert.role.slot_option`); роль `many` без слотов для параметра `one` — в списке с причиной `blueprints.insert.role.incompatible`, выбрать нельзя |
| «Создать роль…» (`bindings.roles.create`) | создаёт роль с именем параметра (если занято — `{param}-2`, видно в поле), кардинальностью и описанием параметра (`blueprints.insert.role.create_hint`); имя и описание можно изменить до вставки; роль появляется в «Привязках» → «Роли узлов сети» (дополнение P1-05 §2.1) |
| Черновик без ролей | подсказка `blueprints.insert.role.none`, список пуст, «Создать роль…» — основной путь |
| Повторяющийся параметр | один параметр заготовки может стоять в нескольких полях (P1-06D §9.2 «тот же параметр») — решение одно на параметр |
| Без выбора | роль **обязательна**: ссылка на узлы без роли в локальном черновике невозможна (`project/v2`); «нужна привязка» для роли не предлагается |

#### 10.2 Параметр-метрика (локальный черновик)

| Элемент | Правило |
|---|---|
| Кандидаты | метрики всех каталогов черновика с тем же типом значения; порядок — сначала совпавшие единицы (`blueprints.insert.status.exact`), затем с другими единицами (`blueprints.insert.status.compatible`, скрыты за «Показать все ({count})»); строка: имя метрики, ключ, единицы, каталог; поиск `blueprints.insert.metric.search` |
| Автовыбор | **никогда**: даже единственный кандидат не отмечается; `blueprints.parameter.no_autopick`, `bindings.mapping.similar_name_not_proof` |
| «Оставить «нужна привязка»» (`blueprints.parameter.leave_unbound`) | всегда доступно; виджет получает ссылку без метрики (O-034), единственная находка P1-04F — `source_binding_required`: сохранить и экспортировать можно, блокируется **только публикация** (O-034 п. 3); `unknown_metric` не возникает — метрика и каталог не указаны, искать нечего; метрика выбирается позже в инспекторе (`blueprints.insert.metric.later`) |
| Параметр без типа значения (`blueprints.parameter.unbound_source`) | кандидаты — все метрики, подпись `blueprints.insert.metric.untyped` |
| Нет подходящих метрик | `blueprints.insert.metric.none`; остаётся «нужна привязка» или «Добавить каталог в библиотеку» (ссылка в «Импорт файлов», P1-03A) |
| Черновик без каталогов | `blueprints.insert.metric.no_catalog` на всех параметрах-метриках; вставка возможна со всеми «нужна привязка» |
| Без решения | параметр без выбранного варианта блокирует «Вставить» (`blueprints.insert.blocked`, 14-08); «Оставить «нужна привязка»» — тоже решение |

#### 10.3 Имя, размер, размещение

- Имя виджета — имя заготовки по умолчанию, можно изменить (`blueprints.insert.widget_name`).
- Размер — `default_size` заготовки, редактируется до вставки (целые ячейки, границы сетки P1-04A); «В первое свободное место: {x}, {y}» пересчитывается при изменении размера; нет места — `editor.chooser.no_space` и подсказка `blueprints.insert.too_big`; существующие виджеты не сдвигаются (`editor.chooser.no_shift`).
- Размещение — как у нового виджета P1-04C: первое свободное место или «Указать на холсте».

#### 10.4 Вставка и результат

1. Одна команда `editor.apply op=add_widget` с `blueprint_id`, `params`, `place`, `size`, `name` (P1-06A §5). Приложение строит виджет `type: zabbix` (O-012 п. 5) из `fields` заготовки: простые значения как есть; параметр-роль → `{kind: host, role, selection}`; параметр-метрика → `{kind: metric, catalog, metric}` или ссылка «нужна привязка»; `reference` — новый, уникальный на панели (P1-01I); `view_mode`, `rf_rate`, период `from/to`, агрегация, фильтры, цвета — из заготовки.
2. Создание роли (10.1) входит в ту же операцию: один шаг истории `editor.op.insert_blueprint`; Ctrl+Z убирает виджет и созданную роль вместе (`blueprints.insert.after.local`). Роль, выбранная из существующих, при отмене не трогается.
3. После вставки виджет выбран, инспектор открыт (как у нового виджета P1-04C); находки пересчитаны: «нужна привязка» → `editor.widget.needs_binding` на виджете; `compatibility_mismatch`, если заявленная совместимость панели у́же вычисленной.
4. Локальный журнал вставок заготовки (`blueprints.inserted`, P1-06C §3) увеличивается; в файл черновика и объект заготовки ничего о связи не пишется — вставленный виджет от заготовки не зависит (`blueprints.insert.independent`).
5. Автосохранение — по P1-04G.

### 11. Копия с сервера (рабочая копия) — решение и обоснование (14-09)

**Решение (принято, Q10 и В-14): вставка в копию с сервера доступна; параметры привязываются к реальным узлам и элементам данных подключения прямо на шаге «Параметры», через экраны P1-05 (09-02 выбор узлов, 09-03 соответствия в режиме «метрика каталога → элемент на узле», дополнение P1-05 §3.1); параметр-метрика сначала получает метрику каталога из библиотеки (заготовка ключей не хранит), затем по её ключу ищется элемент на каждом узле; без подключения или по выбору пользователя параметр остаётся «нужна привязка» и разрешается позже в «Привязках».**

Почему так, а не «недоступно»: вставка виджетов в копию уже предусмотрена P1-04E (вставка из буфера — операция копии «Добавить виджеты на страницу», с вариантом «Оставить ссылку «нужна привязка»»); заготовка — тот же новый виджет без ID сервера, который при публикации создаётся заново (P1-IN-04). Запрет лишил бы главный сценарий (готовая панель Prod + ещё один типовой график) смысла. Почему не роли: у копии ролей нет по дополнению P1-05 §2 — роли появляются только после «Сделать переносимой» (P1-07I); вводить роли в копию ради одной вставки означало бы смешать две модели привязок.

| Параметр | В копии с сервера | Без подключения |
|---|---|---|
| роль `many` | «Выбрать узлы…» → 09-02 (режим роли: заголовок «Параметр «{param}» · несколько узлов», порядок = порядок рядов); результат — список узлов `blueprints.insert.copy.hosts` | «нужна привязка»; узлы — позже в «Привязках» (`blueprints.insert.copy.offline`) |
| роль `one` | 09-02 с одиночным выбором (как «Новый узел») | то же |
| метрика | шаг 1 — «Выбрать метрику каталога…» (`blueprints.insert.copy.choose_metric`): кандидаты — метрики **всех каталогов библиотеки** (у копии своих каталогов нет) по типу значения и единицам параметра, как в §10.2, без автовыбора; выбранная показывается строкой `blueprints.insert.copy.metric_from_catalog`; нет каталогов — `blueprints.insert.copy.no_catalog`, остаётся «нужна привязка». Шаг 2 — после выбора узлов `blueprints.insert.resolve_copy(param, metric_ref, hosts[])`: элемент на каждом узле по ключу выбранной метрики, затем тип значения и единицы (дополнение P1-05 §3.1); статусы P1-IN-03 по узлам (`blueprints.insert.copy.per_host`, покрытие `blueprints.insert.copy.coverage`); «Другой элемент…» → 09-03 (кандидаты, основания, экземпляр LLD вручную); `missing`/`ambiguous`/`denied` на узле — явное решение: «Оставить «нужна привязка» для {host}» или «Выбрать другой элемент данных на {host}…»; смена метрики каталога пересчитывает все узлы | «нужна привязка» |
| метрика без типа | любая метрика каталога, затем любой элемент узла через 09-03 | то же |
| результат | операция копии `add_widget` (O-018) с реальными `hostid`/`itemid` в полях ссылок **внутри операции** (ключ метрики каталога в операции не хранится — только найденные `itemid`), в интерфейсе ID не показываются (P1-04D); виджет виден в «Мои изменения» (P1-08B) как «добавлен»; «нужна привязка» — находка `source_binding_required`, блокирует только публикацию до решения в «Привязках» | — |
| отмена | один шаг истории копии (`editor.op.insert_blueprint`) | — |

Следствие для P1-05: в «Привязках» копии с сервера нужен блок «Ссылки без привязки» для виджетов, вставленных из буфера (P1-04E) и из заготовок, — те же экраны 09-02/09-03 по виджету; это дополнение принятого P1-05 (см. «Что изменится»), не новый экран. Режим «Только чтение» достаточен: выбор узлов и элементов — чтение; запись — только «Публикация».

## 14. Handoff для P4-05, P4-03, P5-01, P2-05 (эскиз; окончательно — P1-06H)

## Проверки приёмки P1-06E–F

- Редактор профиля показывает только поля классов «профиль» и «по выбору» матрицы P1-06B, в порядке разделов инспектора, с флажком включения; поля класса «никогда» в редакторе отсутствуют; тип виджета профиль не меняет.
- Зависимые поля при включённом управляющем поле недоступны с причиной и не хранятся; при невключённом — помечены «применится, если допускает виджет».
- Проверка значений — рядом с полем сразу после ввода; профиль с ошибками не сохраняется; «Сохранить» недоступна с причиной; каждое сохранение увеличивает `version` и не меняет ни один черновик; встроенный профиль открывается только для просмотра с «Дублировать для изменения»; `unknown` не открывается.
- Предпросмотр — синтетика P1-04I на встроенном примере, с меткой «Синтетика», на фиксированной светлой поверхности Zabbix; в тёмной теме приложения выглядит так же; никуда не сохраняется.
- Цвет палитры ниже 3:1 к белому — предупреждение, не блокировка.
- Вставка заготовки идёт из «Добавить виджет» → «Из заготовок»; параметр-роль — роль черновика или созданная роль; параметр-метрика — метрика каталога по типу значения и единицам со статусами; ни один источник не выбирается автоматически; «Оставить «нужна привязка»» допустимо, даёт только находку `source_binding_required` и блокирует только публикацию (сохранение и экспорт возможны); параметр без решения блокирует вставку.
- Вставка — одна операция `add_widget` с `blueprint_id` и один шаг истории `editor.op.insert_blueprint` (вместе с созданной ролью); `reference` выдаёт ZDashstitch; размер по умолчанию из заготовки; существующие виджеты не сдвигаются.
- В копии с сервера параметр-роль привязывается к реальным узлам, параметр-метрика — к метрике каталога библиотеки и по её ключу к элементам на узлах через экраны P1-05 без показа ID; без подключения — «нужна привязка»; заготовки `unknown` и типы без `create` не вставляются с причиной.
- Все экраны проходимы с клавиатуры; состояния не передаются только цветом; фокус после окна возвращается на кнопку или вставленный виджет.

## Открытые вопросы владельцу

1. **Профиль с ошибками не сохраняется** (§4; рекомендация) — или допускать сохранение в состоянии `invalid`, как у импортированных файлов (тогда «Сохранить» всегда доступна, а применить нельзя до исправления).
2. **Вставка заготовки в копию с сервера** (§11; рекомендация: доступна, параметры привязываются к реальным узлам и элементам через экраны P1-05 на шаге «Параметры», без подключения — «нужна привязка») — или недоступна в MVP с подписью «только в локальных панелях» (проще, но лишает сценария «добавить типовой график в готовую панель Prod»).
3. **Единицы порогов в профиле `item`:** хранить справочное поле `thresholds_units` в разделе `item` (рекомендация; нужно предупреждению `units_differ` при применении и подсказке в редакторе) — затрагивает эскиз схемы P1-06A §4 до её утверждения по `DOC_GOVERNANCE`.
4. **Примеры предпросмотра** (§5): фиксированный набор из шести примеров (рекомендация) — или предпросмотр на выбранном виджете открытого черновика (требует черновика и даёт не повторяемую картинку).
5. **Тёмная тема Zabbix в предпросмотре:** не в MVP (рекомендация; поверхность — светлая тема Zabbix 7.4, предупреждение о контрасте считается к белому) — или переключатель «светлая/тёмная тема Zabbix» в предпросмотре.
6. **Создание роли из окна вставки в том же шаге истории** (§10.4; рекомендация: Ctrl+Z убирает роль вместе с виджетом) — или роль создаётся отдельным шагом до вставки.
7. **Встроенные профили в редакторе:** открывать для просмотра с «Дублировать для изменения» (рекомендация) — или не открывать вовсе (только карточка и «Дублировать»).
