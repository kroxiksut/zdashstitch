## 1. Точки входа и область применения

| Откуда | Действие | Начальная область | Начальный режим |
|---|---|---|---|
| инспектор виджета → меню «Ещё» → «Применить профиль…» (`profiles.action.apply`, есть в P1-00F); меню виджета на холсте | окно «Применить профиль» (14-10) | «виджету «{widget}»»; при выборе нескольких — «выбранным виджетам: N» | первое применение — `replace` (§5.1, вопрос 1) |
| меню страницы редактора (вкладка страницы, P1-04B) → «Применить профиль к странице…» | то же | «всем совместимым виджетам страницы «{page}»» | `replace` |
| «Структура» (P1-01B) → меню панели → «Применить профиль ко всей панели…» | то же | «всем совместимым виджетам панели ({pages} страниц)» | `replace` |
| тост после «Сохранить оформление как профиль» → «Применить к другим виджетам…» (P1-06D §8.3) | то же, профиль уже выбран | страница источника, виджет-источник отмечен как «уже совпадает» | `replace` |
| инспектор → баннер «профиль обновлён до версии {version}» → «Обновить из профиля…» (`profiles.action.update_from_profile`) | окно «Обновить из профиля» (14-11) | «виджету «{widget}»» | `keep_local` (O-012 п. 2) |
| инспектор → сводка «Из профиля «{profile}»» → «Обновить из профиля…» (виджет на текущей версии) | то же («Все виджеты из этого профиля — на текущей версии», обновлять можно: вернуть значения профиля всем) | виджет | `keep_local` |
| карточка профиля в библиотеке (14-01) | применения **нет** (P1-06C §4): только счётчик «из них на прежней версии — K» и подсказка «обновление — в редакторе черновика» | — | — |

Область применения всегда выбирается внутри окна (§2), точка входа лишь задаёт начальное значение. «Вся панель» охватывает все страницы черновика-панели; у черновика-страницы этот вариант отсутствует. Условия: вкладка правит черновик (P1-01C §3; иначе окно не открывается — `draft_open_elsewhere`), библиотека доступна, профиль в состоянии `ok` (§2.1). Подключение не требуется.

## 2. Окно «Применить профиль» (14-10)

Модальное окно поверх редактора (как 14-04); левая колонка — выбор и таблица виджетов, правая — итог, предупреждения и действия. Черновик не меняется до нажатия «Применить».

### 2.1 Профиль

Выпадающий список профилей библиотеки: имя, версия, типы виджетов (`profiles.apply.profile`). Доступны только профили в состоянии `ok` (P1-06C §6); `invalid` и `unknown` показаны в списке с причиной и не выбираются (`profiles.apply.profile.unavailable` с `profiles.state.invalid_hint` / `profiles.state.unknown_adapter_hint`); встроенные профили применяются как любые другие. Профиль без раздела для типов, присутствующих в области, не блокируется: такие виджеты попадают в «пропущено» с причиной `type_not_in_profile`.

### 2.2 Область

Группа переключателей «Применить к» (`profiles.apply.scope`):

| Вариант | ID | Когда есть |
|---|---|---|
| виджету «{widget}» | `profiles.apply.scope.widget` | выбран один виджет |
| выбранным виджетам: {count} | `profiles.apply.scope.selected` | выбрано ≥ 2 |
| всем совместимым виджетам страницы «{page}» | `profiles.apply.scope.page` | всегда |
| всем совместимым виджетам панели ({pages} страниц) | `profiles.apply.scope.dashboard` | черновик-панель |

При смене области таблица §2.4 и итог пересчитываются; раскрытое «было → станет» остаётся на том же виджете, если он в области.

### 2.3 Режим для уже изменённых полей

Группа «Поля, уже изменённые в виджетах» (`profiles.apply.mode`) с тремя вариантами `profiles.apply.mode.replace` / `keep_local` / `merge` (ID из P1-06A) и пояснениями `profiles.apply.mode.*_hint`. Точная семантика — §5. В окне первого применения по умолчанию `replace`; в окне «Обновить из профиля» — `keep_local` (§6).

### 2.4 Таблица виджетов

Строки — все виджеты области (включая несовместимые: пользователь видит, почему что-то пропущено), порядок — страницы черновика, внутри страницы — порядок чтения (P1-04A). Колонки: «Виджет» (имя, тип `widget.type.<id>`), «Страница» (только для области «панель»), «Совместимость» (короткая плашка уровня §3 — `profiles.compatibility.badge.*`; полный текст `profiles.compatibility.*` — в подсказке и для чтения с экрана), «Поля» («{applied} из {total}» — применимые из включённых полей раздела профиля для этого типа; для пропущенных — «пропущен» и причина).

Щелчок по строке (Enter) раскрывает под ней таблицу «Было → станет» (§4). Переключатель «Показать пропущенные ({count})» сворачивает строки `incompatible`, когда их много (по умолчанию показаны). Для области «панель» строки группируются заголовками страниц.

### 2.5 Итог, предупреждения, действия (правая колонка)

- Итог: `profiles.apply.summary` («Применится к {full}, частично к {partial}, пропущено {skipped}») и `profiles.apply.summary.fields` («Изменится полей: {changed} в {widgets} виджетах; уже совпадают: {unchanged}»). Если ни одно значение не изменится — `profiles.apply.nothing`, «Применить» недоступна с этой причиной; если в области нет совместимых виджетов — `profiles.apply.no_targets`.
- Предупреждения (не блокируют): палитра короче числа рядов (`profiles.apply.warning.palette_repeats_widgets`, P1-06B §8), единицы порогов (§7), неизвестные единицы (`profiles.apply.warning.units_unknown`), виджеты в старом виде файла (`profiles.apply.legacy_widgets`), смена профиля у виджета (`profiles.apply.switch_profile`, §5.3), `view_mode` в профиле (`profiles.apply.view_mode_hint`).
- Постоянные подсказки: `profiles.apply.untouched` («Источники, период, фильтры и расположение не меняются»), `profiles.hint.copy_semantics`, `profiles.apply.undo_hint` («Один шаг отмены: Ctrl+Z вернёт все виджеты сразу»), для копии с сервера — `profiles.apply.copy_hint` (§8).
- Кнопки: «Отмена», «Применить к {count} виджетам» (`profiles.apply.action.count`; при одном виджете — `profiles.apply.action`). Основная кнопка недоступна с причиной, пока область пуста или нечего менять.

### 2.6 Подтверждение и настройка `editor.confirm_bulk_apply`

Окно и есть подтверждение: до «Применить» черновик не меняется, и таблица «было → станет» доступна по каждому виджету (требование P1-06A §3.2 «ничего не меняется молча»). Настройка P1-09E «Спрашивать перед массовыми действиями» (`editor.confirm_bulk_apply`, по умолчанию `true`) действует так:

| Точка входа | `confirm_bulk_apply = true` | `confirm_bulk_apply = false` |
|---|---|---|
| «Применить профиль…» (профиль ещё не выбран) | окно | окно (выбор профиля необходим) |
| тост «Применить к другим виджетам…» (профиль и страница известны) | окно с заполненными полями | применяется сразу к странице в режиме `replace`; тост результата с «Отменить» |
| «Обновить из профиля…» для одного виджета без полей «изменено после профиля» и без предупреждений | окно | применяется сразу в `keep_local`; тост результата с «Отменить» |
| «Обновить из профиля…» для одного виджета с правками после профиля или с предупреждениями | окно | окно (есть выбор режима) |
| область «страница» / «панель» из меню | окно | окно (область выбирается в окне) |

Об этом сказано в окне подписью `profiles.apply.confirm_hint`. Прямое применение без окна всё равно одна операция с одним шагом отмены и тостом `profiles.apply.done`.

## 3. Совместимость по включённым полям

Совместимость считается в `application` перед показом окна и пересчитывается при смене профиля, области и режима; результат — коды и параметры (`profiles.compatibility`, §11), текст собирает интерфейс.

### 3.1 Уровень виджета

Проверки по порядку; первая сработавшая даёт уровень `incompatible`/`unknown`, иначе уровень определяется полями:

| № | Условие | Уровень | Причина (ID) |
|---|---|---|---|
| 1 | адаптер профиля ≠ адаптер черновика (у копии — версия подключения; у локального — `adapter` черновика), или профиль новее приложения | `unknown` | `profiles.state.unknown_adapter_hint` |
| 2 | тип виджета `registry_state: unknown` | `incompatible` | `profiles.compatibility.reason.edit_unsupported` |
| 3 | у типа нет флага `edit` в реестре точной версии (`clock`, `problems`, остальные 28) | `incompatible` | `profiles.compatibility.reason.edit_unsupported` (`common.state.edit_unsupported` в инспекторе) |
| 4 | у профиля нет раздела для типа | `incompatible` | `profiles.compatibility.reason.type_not_in_profile` |
| 5 | раздел профиля пуст (не бывает у `ok`-профиля; защита) | `incompatible` | `profiles.compatibility.reason.type_not_in_profile` |
| 6 | виджет хранится в типизированном виде `graph`/`item_value` старого файла (O-034 п. 7) | `partial` | `profiles.compatibility.reason.legacy_widget_view`; применима только палитра → `series.color` |
| 7 | все включённые поля раздела применимы (§3.2) | `compatible` | — |
| 8 | часть полей неприменима | `partial` | список полей с причинами |

Виджет с `partial`, у которого **ни одно** поле не применимо (все зависимы/неизвестны/единицы), показывается как `partial` «0 из N» и в операцию не попадает — он не считается «применённым» и метки происхождения не получает.

### 3.2 Исход по полю

Для каждого включённого поля раздела (для `svggraph` — `widget_fields`, `dataset_fields` на каждый набор `ds.N`, палитра; для `item` — `widget_fields`, пороги; `view_mode` — атрибут):

| Исход | Условие | Подпись в «было → станет» | Считается в |
|---|---|---|---|
| `apply` | поле применимо и значение отличается | `profiles.apply.outcome.apply` «изменится» | `changed` |
| `reset_default` | значение профиля равно умолчанию Zabbix, у виджета — иное; поле снимается кодеком (P1-06A §3.1) | `profiles.apply.outcome.reset_default` | `changed` |
| `unchanged` | значение уже совпадает (с учётом «умолчание = отсутствие поля») | `profiles.apply.outcome.unchanged` | `unchanged`; метка происхождения всё равно ставится (§6.1) |
| `kept_local` | режим `keep_local`/`merge` оставляет локальное значение (§5) | `profiles.apply.outcome.kept_local` | `kept` |
| `skipped_dependent` | управляющее поле **не включено** в профиль, а его значение у виджета исключает зависимое (`fill`/`width` при `ds.N.type` = столбцы у виджета, `pointsize` при виде ≠ точки, `legend_*` при `legend` = нет, `*_color`/`*_size` при пункте вне `show`, `graph_item_problems`/`simple_triggers`/`working_time` при `show_problems` = нет, `lefty_*` при `lefty` = нет; таблица «сверить» P1-06B §8) | `profiles.apply.outcome.skipped_dependent` с `profiles.compatibility.reason.field_dependent` | `skipped` → виджет `partial` |
| `skipped_unknown` | поле у виджета помечено `registry_state: unknown` (O-034 п. 5) | `profiles.apply.outcome.skipped_unknown` | `skipped` → `partial` |
| `skipped_units` | пороги `item`: единицы профиля (`thresholds_units`) известны, единицы метрики виджета известны и отличаются (§7) | `profiles.apply.outcome.skipped_units` с `profiles.compatibility.reason.units_differ` | `skipped` → `partial`; переключатель §7 переводит в `apply` |
| `skipped_legacy` | старый вид виджета (§3.1 п. 6): все поля, кроме палитры | — (одна причина на виджет) | `partial` |

Если управляющее поле включено в профиль, зависимое поле профиль уже не содержит (P1-06E §3) — такого случая при применении нет. Поля класса «никогда» (источники, время, агрегация, фильтры, тексты, связи, геометрия, `rf_rate`, неизвестные поля) в профиле отсутствуют и не рассматриваются: это гарантирует схема профиля (P1-06H), а не проверка при применении.

Палитра `series_palette`: цвета назначаются рядам по порядку наборов и элементов списка (`ds.N.color` для набора-шаблона, `ds.N.color.M` для набора-списка); рядов больше, чем цветов — повтор по кругу с предупреждением; `color_palette` вместо своей палитры — пишется `ds.N.color_palette`, а `ds.N.color`/`color.M` снимаются до умолчания. Для `item` палитра не используется (цвет спарклайна `sparkline.color` — обычное поле раздела).

## 4. Таблица «Было → станет»

По виджету — таблица полей раздела профиля (`profiles.apply.diff.title`), в порядке разделов инспектора P1-04D (как 14-06): «Поле» (человеческое имя из описания формы; имя API — в подсказке и «Технических сведениях»), «Было» (значение виджета с плашкой происхождения: `editor.field.default_zabbix`, `editor.field.changed`, `profiles.field.origin.profile`, `profiles.field.origin.overridden`), «Станет» (значение профиля или «—», если не применяется), «Итог» (исход §3.2). Поля `dataset_fields` показываются одной строкой на поле с подписью `profiles.editor.applies_all_datasets`; если у наборов разные значения — «было» перечисляет их через «·» (как 14-04 «У наборов разные значения»). Палитра — одной строкой с цветными квадратами и текстовыми значениями.

Таблица обязана существовать для каждого виджета области уровня `compatible`/`partial` до нажатия «Применить» (P1-06A §3.2); для области «панель» она считается лениво при раскрытии строки, а итоги — сразу для всех.

## 5. Режимы и локальные правки

### 5.1 Первое применение (виджет без меток этого профиля)

| Режим | Поля «умолчание Zabbix» | Поля «изменено» (своя правка или скопировано с сервера) | Метка после |
|---|---|---|---|
| `replace` (по умолчанию в окне первого применения) | значение профиля | значение профиля | «из профиля» на всех применённых полях |
| `keep_local` | значение профиля | остаются (`kept_local`) | «из профиля» — только на полях, получивших значение профиля или уже совпадающих; остальные — «изменено» |
| `merge` | значение профиля | остаются | как `keep_local` (прежней версии профиля у виджета нет, «новых полей» — все, см. §5.2) |

Почему `replace` по умолчанию при первом применении: пользователь явно выбрал профиль для приведения виджетов к единому виду; значения, скопированные с сервера, в редакторе помечены «изменено» (P1-04D), и `keep_local` оставил бы у копии с сервера почти всё как есть. O-012 п. 2 относится к повторному применению. Это вопрос 1 владельцу.

### 5.2 Повторное применение («Обновить из профиля», та же `profile_id`)

Расширяет P1-06A §3.2.1 на все состояния; «запись применения» — локальные метаданные `{profile_id, profile_version, fields}` (P1-06A §3.3), где `fields` — имена и значения на момент последнего применения.

| Состояние поля виджета | `replace` | `keep_local` (по умолчанию) | `merge` |
|---|---|---|---|
| «из профиля» (значение = записанное) | значение профиля | значение профиля | значение профиля |
| «изменено после профиля» (поле есть в записи, значение другое) | значение профиля | остаётся | остаётся |
| «изменено», поля в записи **нет**, в профиле теперь есть | значение профиля | остаётся | **значение профиля** (новое поле профиля) |
| «умолчание Zabbix», поля в записи нет, в профиле теперь есть | значение профиля | значение профиля | значение профиля |
| поле есть в записи, из профиля **убрано** | остаётся; метка → «изменено» (`profiles.update.removed_fields`) | то же | то же |
| поле у виджета `unknown`, зависимое, пороги с другими единицами | по §3.2 (не трогается) | то же | то же |

После операции запись применения заменяется новой (`profile_version` = текущая, `fields` = фактически записанные значения плюс поля `kept_local`, помеченные как `overridden`, чтобы метка «изменено после профиля» сохранилась). Отмена возвращает прежнюю запись.

### 5.3 Другой профиль поверх применённого

Виджет с меткой профиля B, к которому применяют профиль A: это первое применение A (§5.1). Предупреждение `profiles.apply.switch_profile` в итоге: метки переходят к A; поля, которые были «из профиля B» и которых нет в A, сохраняют значения и становятся «изменено»; поля B, которые есть и в A, получают значение A по режиму (в `keep_local` «из профиля B» считается не локальной правкой, а значением профиля — заменяется). Виджет перестаёт учитываться в `profiles.used_by` профиля B.

### 5.4 Что не меняется ни в одном режиме

Источники, время, агрегация, фильтры, тексты, связи, геометрия, `rf_rate`, неизвестные поля и типы (P1-06A §2); тип виджета; поля, не включённые в профиль; виджеты уровня `incompatible`/`unknown`.

## 6. Происхождение значения в инспекторе и метки (14-12)

### 6.1 Состояния поля

Дополняет P1-04D («умолчание Zabbix» / «изменено», «Вернуть умолчание») состояниями P1-06A §3.1:

| Состояние | Плашка | Условие | Действия у поля |
|---|---|---|---|
| умолчание Zabbix | `editor.field.default_zabbix` | поле не записано | — |
| изменено | `editor.field.changed` | значение ≠ умолчание; записи профиля для поля нет | «Вернуть умолчание» |
| из профиля | `profiles.field.origin.profile` («из профиля «{profile}»») | поле есть в записи применения, значение = записанному (включая исход `unchanged` при применении и значение-умолчание, записанное профилем) | «Вернуть умолчание», «Отвязать от профиля» (`profiles.field.action.detach`) |
| изменено после профиля | `profiles.field.origin.overridden` | поле есть в записи, значение ≠ записанному | «Вернуть значение профиля» (`profiles.field.action.restore_profile` — значение из записи, не из текущей версии профиля), «Вернуть умолчание» |

Подсказка у плашки: `profiles.field.origin.profile_version` («из профиля «{profile}», версия {version}»); для «изменено после профиля» — `profiles.field.origin.changed_value` («в профиле: {value}» — записанное значение). Имя профиля берётся по `profile_id` из библиотеки (переименование видно сразу); если профиль удалён — метки при открытии черновика лениво переводятся в «изменено» (P1-06C §11), а в сводке виджета один раз показывается `profiles.widget.profile_deleted`.

Действия у поля — обычные правки `editor.apply op=edit_field` (шаг `editor.op.edit_field`); «Отвязать от профиля» — `editor.apply op=detach_profile {widget_refs: [виджет], fields: [поле]}`: операция без изменения значения, меняющая только запись применения (шаг истории `editor.op.detach_profile` есть, чтобы Ctrl+Z вернул метку; у копии — операция `apply_style_profile` с пустым списком значений, в отличие от служебной метки у источника P1-06D §8.5 — обычная, отменяемая). Подтверждения нет (P1-00E §9: действие обратимо и ничего не теряет).

### 6.2 Сводка виджета

Только в разделе «Основное» инспектора (решение В-18; в других разделах сводки нет, баннер устаревания §6.3 виден над разделами в любом из них) у виджета с записью применения: строка `profiles.widget.origin.summary` («Из профиля «{profile}»: полей {fields}, изменено после — {overridden}») со ссылкой на карточку профиля (P1-06C §1), кнопки «Обновить из профиля…» и в меню «Ещё» (`common.action.more`) — «Вернуть все значения профиля» (`profiles.field.action.restore_all`: все поля «изменено после профиля» → записанные значения; одна операция `editor.apply op=apply_profile {scope: {widget_refs: [виджет]}, mode: replace, from_record: true}` — значения берутся из записи применения, а не из текущей версии профиля, запись и её `profile_version` не меняются; шаг `editor.op.apply_profile`), «Отвязать виджет от профиля» (`profiles.field.action.detach_all` с подсказкой `profiles.field.detach_hint`: `op=detach_profile {widget_refs: [виджет]}` без `fields` — значения остаются, запись удаляется, виджет не учитывается в `profiles.used_by`; без подтверждения, шаг истории).

### 6.3 Устаревшая версия (`origin.outdated`)

| Что | Правило |
|---|---|
| Обнаружение | при открытии черновика и при каждом сохранении профиля/замене при импорте (P1-06C §5): `profile_version` записи < `version` профиля в библиотеке |
| Где видно | баннер в инспекторе виджета `profiles.widget.outdated.banner` («Профиль «{profile}» обновлён до версии {version}. У виджета — версия {current}») с кнопкой «Обновить из профиля…» — над содержимым раздела, в любом разделе инспектора (14-12); плашки полей остаются «из профиля» (значения не менялись); карточка профиля — `profiles.used_by.outdated`; в окне применения — фильтр `profiles.apply.filter.outdated_only` |
| Чего нет | находки в «Проверках» (устаревание — не ошибка черновика и не влияет на экспорт и публикацию, P1-04F); автоматического обновления; баннера на уровне черновика (достаточно инспектора и карточки; вопрос 4) |
| Версия выше у виджета, чем в библиотеке | возможно после «Сохранить как копию» при импорте или удаления и повторного импорта старого файла: показывается тот же баннер с подписью версий; «Обновить» применяет текущую версию библиотеки |
| Профиль `invalid` | «Обновить из профиля…» недоступна с `profiles.update.profile_invalid` |
| Профиль `unknown` (адаптер) | недоступна с `profiles.state.unknown_adapter_hint` |
| Профиль удалён | баннера нет; метки → «изменено»; `profiles.update.profile_deleted` только если окно было открыто в момент удаления |

### 6.4 Окно «Обновить из профиля» (14-11)

То же окно, что §2, в режиме обновления: заголовок `profiles.update.title`, подзаголовок `profiles.update.subtitle` («Виджеты на версии {from}; в библиотеке — версия {to}») и `profiles.update.outdated_count`; профиль фиксирован (`profile_id` записи); область — виджет / все виджеты из этого профиля на странице / во всей панели (строки — только виджеты с записью этого профиля; фильтр «только на прежней версии» включён по умолчанию, если такие есть); режим по умолчанию `keep_local` (O-012 п. 2); таблица «было → станет» с плашками происхождения (§4) и колонкой «Итог» по §5.2; строка `profiles.update.removed_fields` для полей, убранных из профиля; если все виджеты на текущей версии — `profiles.update.up_to_date`, обновлять всё равно можно (вернёт значения профиля полям «изменено после профиля» в режиме `replace`).

### 6.5 Где хранится и чего не содержит

Запись применения — локальные метаданные черновика (O-018; P1-06A §3.3): для локального черновика — файл рядом с черновиком в хранилище приложения (не в `project/v2`, не в пакете, не в экспорте; при экспорте и импорте на другой машине метки отсутствуют — все значения «изменено»); для копии с сервера — внутри операции `apply_style_profile` (§8). Запись не содержит ID сервера, узлов, элементов, подключения; имена профилей — по ссылке `profile_id`. Операция «Дублировать» черновика копирует записи; «Сделать переносимой» (P1-07I) сохраняет записи у новой локальной панели (они локальные, формату не мешают).

## 7. Пороги и единицы

Пороги `item` включаются в профиль только парой «порог + цвет» и со справочным полем `thresholds_units` раздела `item` (P1-06E §3, вопрос 3 P1-06E–F → сводный вопрос в P1-06H).

| Единицы профиля (`thresholds_units`) | Единицы элемента виджета | Исход |
|---|---|---|
| заданы | известны и совпадают (без учёта регистра и пробелов) | `apply` |
| заданы | известны и отличаются | `skipped_units` (`profiles.compatibility.reason.units_differ`) → `partial`; переключатель в окне «Применить пороги, даже если единицы отличаются» (`profiles.apply.thresholds.force`, выключен, один на окно) переводит в `apply` с предупреждением в итоге |
| заданы | неизвестны | `apply` с предупреждением `profiles.apply.warning.units_unknown` |
| не заданы | любые | `apply` без предупреждения (профиль не утверждает единиц) |
| поле `units` виджета задано вручную (замена единиц элемента, «по выбору» P1-06B §9) | — | сравнивается с `units` виджета, а не метрики; если профиль одновременно включает `units`, сравнение идёт с единицами профиля |

Откуда известны единицы элемента: локальный черновик — из метрики каталога (`metrics/v1`, `units`), «нужна привязка» — неизвестны; копия с сервера — из локальных метаданных элементов копии (I-4 P1-04H, P2-05), иначе неизвестны. Границы и единицы осей `svggraph` (`lefty_min/max`, `*_units`, `*_static_units`) применяются без проверки единиц — только с предупреждением класса «по выбору» в итоге (O-012 п. 3).

## 8. Копия с сервера (рабочая копия)

| Что | Правило |
|---|---|
| Операция | `apply_style_profile` в списке операций копии (O-018, Base + операции): `{profile_id, profile_version, profile_name_at_apply, mode, widgets: [{widget_ref, fields: [{name, before, after, outcome}], view_mode?}]}`; `widget_ref` — ссылка копии (серверный `widgetid` базы или локальный ID добавленного виджета), в интерфейсе ID не показываются (P1-04D) |
| Шаг истории | один (`editor.op.apply_profile`), как у «Принять точные» (P1-04G §4.2); отмена снимает операцию |
| Происхождение значения | только в операции (P1-06A §3.3): метки «из профиля»/«изменено после профиля» в инспекторе считаются из цепочки операций (`apply_style_profile` + последующие `set_widget_field` по тем же полям); в снимок, публикацию и `deployment-state/v1` ничего о профиле не попадает |
| «Мои изменения» (P1-08B) | строка `profiles.apply.changes_entry` («Применён профиль «{profile}»: полей — {fields}») с раскрытием по виджетам и полям «база → черновик»; при публикации поля пишутся существующими кодеками `item`/`svggraph` как обычные изменения полей (P1-06B §7); профиль ничего не добавляет к контракту записи P0-06 |
| Предварительные проверки P1-08C | те же, что для правок полей (`capability_not_verified` по реестру точной версии подключения); если версия сервера при публикации отличается от `adapter` профиля — проверки блокируют запись полей, как любую правку, профиль здесь не при чём |
| «Скопировать заново» (P1-03E) | операция переигрывается на новой базе по полям: поле, изменённое на сервере с момента базы, — «Конфликт» по правилам P1-03E («Оставить серверное» / «Применить моё») с подписью `profiles.apply.copy.conflict`; виджет, исчезнувший на сервере, — «цель исчезла» (P1-03E); поля, совпавшие с новой базой, — «уже совпадает» |
| Совместимость | как §3, по реестру версии подключения копии; типы без `edit` — `incompatible` даже у виджетов, скопированных целиком (P1-06B §7) |
| Без подключения | применение доступно: операция локальная; единицы элементов — из локальных метаданных копии или неизвестны (§7) |
| Виджеты, добавленные в копию (из буфера, из заготовки) | применимы так же; их `widget_ref` — локальный |

## 9. Операция, история, автосохранение (локальный черновик)

- Одна команда `editor.apply op=apply_profile {profile_id, profile_version, mode, scope{widget_refs[] | page | dashboard}, force_thresholds, from_record?}` на всю область, в том числе для «всей панели» через несколько страниц: один шаг истории `editor.op.apply_profile` («применение профиля «{profile}»»); Ctrl+Z возвращает все виджеты и прежние записи применения разом; подпись в «Отменить: …» (P1-04G). Конкретные значения полей вычисляет `application` (`profiles.compatibility` → применение), интерфейс передаёт решения (профиль, область, режим, переключатель порогов), а не значения; значения по виджетам `[{widget_ref, fields: [{name, before, after, outcome}], view_mode?}]` появляются только в операции рабочей копии (§8). `from_record: true` — вариант «Вернуть все значения профиля» (§6.2): источник значений — запись применения виджета, версия записи не меняется.
- Находки P1-04F пересчитываются после операции для затронутых виджетов (значения профиля допустимы по схеме профиля, новых `field_invalid` быть не должно; если описание формы адаптера строже — находка у поля, как при обычной правке).
- Автосохранение — по P1-04G; при `storage_unavailable` операция в памяти остаётся, как любая правка.
- Применение не создаёт и не снимает находок «нужна привязка», не меняет роли, каталоги и геометрию; «Проверки» не получают новых групп.
- Два окна (вкладки) одного черновика — правило P1-01C §3: окно применения открывается только во вкладке, правящей черновик.

## Проверки приёмки P1-06G

- Применение возможно к одному виджету, выбранным, всем совместимым виджетам страницы и всей панели; область выбирается в окне; до «Применить» черновик не меняется, и таблица «было → станет» доступна для каждого виджета области.
- Уровни `compatible/partial/incompatible/unknown` вычисляются по реестру P0-09 точной версии и включённым полям профиля; зависимые поля при невключённом управляющем поле, неизвестные поля виджета и пороги с другими единицами пропускаются с причиной; типы без `edit` и неизвестные типы перечисляются как пропущенные и не меняются.
- Режимы `replace` / `keep_local` / `merge` действуют по таблицам §5.1–§5.2; первое применение — `replace` по умолчанию (вопрос 1), «Обновить из профиля» — `keep_local` (O-012 п. 2); поля, убранные из профиля, сохраняют значение и становятся «изменено».
- Применение — одна операция `editor.apply op=apply_profile` и один шаг истории `editor.op.apply_profile` даже для всей панели; Ctrl+Z возвращает все виджеты и записи применения разом; `project/v2`, пакет и экспорт не содержат ни `profile_id`, ни меток.
- Инспектор показывает четыре состояния поля с действиями «Вернуть умолчание», «Отвязать от профиля», «Вернуть значение профиля»; сводка «Из профиля…» и действия виджета — только в разделе «Основное»; баннер устаревания виден в любом разделе, появляется только при разнице версий и не создаёт находок; удаление профиля переводит метки в «изменено»; отвязка — без подтверждения, с шагом истории.
- Для копии с сервера применение — операция `apply_style_profile` в списке операций, видна в «Мои изменения», публикуется существующими кодеками, при «Скопировать заново» конфликтует по полям; происхождение значения не публикуется.
- Настройка `editor.confirm_bulk_apply` пропускает окно только для действий с известным профилем и областью; результат всегда — тост с «Отменить».
- Все экраны проходимы с клавиатуры; уровни и состояния переданы текстом, не только цветом; фокус после окна возвращается на исходный элемент.

## Открытые вопросы владельцу

1. **Режим первого применения по умолчанию — `replace`** (§5.1; рекомендация: пользователь явно выбрал профиль, а значения копии с сервера помечены «изменено» и при `keep_local` не изменились бы) — или `keep_local` везде, как при повторном применении (O-012 п. 2 буквально).
2. **Пороги с другими единицами:** пропускать с причиной и давать явный переключатель «Применить пороги, даже если единицы отличаются» (§7; рекомендация) — или применять всегда с предупреждением, без переключателя (проще, но меняет цвета значений с другими единицами молча).
3. **`editor.confirm_bulk_apply = false`** пропускает окно для действий с известным профилем и областью (§2.6; рекомендация, с «Отменить» в тосте) — или окно показывается всегда, а настройка на профили не влияет.
4. **Устаревшие версии:** только баннер инспектора и счётчик карточки (§6.3; рекомендация) — или ещё баннер на уровне черновика «N виджетов на прежней версии профиля» в «Обзоре».
5. **Смена профиля поверх другого (§5.3):** поля прежнего профиля, которых нет в новом, становятся «изменено» (рекомендация) — или возвращаются к умолчанию Zabbix (чище, но теряет значения, которых пользователь не менял).
6. **Отвязка от профиля** — шаг истории (рекомендация: Ctrl+Z возвращает метки) — или действие без шага истории, как метка у источника при извлечении (P1-06D §8.5).
