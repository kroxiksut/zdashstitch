## P1-02A — список подключений

Карточка профиля: имя, плашка состояния, нормализованный адрес моноширинным шрифтом, строка «версия · время последней проверки · способ входа и где хранится секрет», предупреждение для `http`. Секрет, пароль и токен не показываются ни на карточке, ни в поиске. Действия: «Подключиться» / «Отключиться», «Проверить», «Изменить»; «Дублировать» и «Удалить» — в редакторе.

| Состояние | Что видно | Действия |
|---|---|---|
| Нет профилей | «Подключений пока нет», объяснение, что локальная работа не требует сервера | «Новое подключение», «Продолжить без подключения» |
| Загрузка списка | скелет карточек | — |
| Профиль не подключён | «Не подключено», последняя подтверждённая версия и время | «Подключиться», «Изменить» |
| Подключение идёт | «Подключение…», шаги P1-02D | «Отмена» |
| Подключён | «Подключено · только чтение» или «· чтение-запись», рамка активного профиля | «Отключиться», «Изменить» |
| Последняя проверка неудачна | «Последняя проверка: ошибка» и текст ошибки по коду | «Проверить», «Изменить» |
| Нужен вход | «Нужен вход» (истёк токен или сессия) | «Войти», «Изменить» |

Одновременно активен один профиль. Переключение на другой профиль отключает текущий; правила для черновиков и планов — P1-01C §4 и P1-02G.

## P1-02B — адрес и идентичность профиля

Поле «Адрес Zabbix» принимает адрес так, как он выглядит в браузере: схема `http` или `https`, имя или IPv4/IPv6 в квадратных скобках, необязательный порт и базовый путь. Под полем сразу показывается вычисленный адрес API.

Нормализация (повторяет `ZabbixEndpoint`): схема и имя в нижнем регистре; стандартный порт убирается; путь получает завершающий `/`; адрес API вычисляется разбором URL относительно базового пути, а не склейкой строк. Отклоняются: отсутствие схемы, схемы кроме `http`/`https`, имя пользователя или пароль в адресе, фрагмент `#…`, строка запроса `?…`.

- Переименование профиля не меняет сервер. Смена схемы, имени, порта или пути — это другой сервер: показывается «Это другой сервер», после сохранения привязки и планы этого подключения требуют повторной проверки, а свежесть источников становится `stale`.
- Для `http` показывается предупреждение, что данные входа идут открытым текстом. Сохранить профиль `http` с сохранённым токеном можно только после явного подтверждения.
- Примеры в макете используют только зарезервированные имена и адреса документации (`example.invalid`, `192.0.2.0/24`, `2001:db8::/32`).

## P1-02C — вход и жизненный цикл секрета

Переключатель «API-токен | Имя пользователя и пароль» (взаимоисключающие варианты).

| | API-токен | Имя пользователя и пароль |
|---|---|---|
| Хранение | по выбору пользователя в системном хранилище («Сохранить токен в системном хранилище», по умолчанию выключено), иначе только в памяти процесса | пароль не сохраняется никогда, спрашивается при каждом подключении; имя пользователя хранится в профиле |
| Проверка | явный шаг `user.checkAuthentication` (P1-IN-01: токен иначе не проверяется сервером при входе) | `user.login`, затем первый вызов (роль без API и MFA видны только на нём) |
| MFA | работает | недоступно: «Для этой учётной записи с MFA нельзя войти по паролю…» (`connection.auth.mfa_token_required`) |
| LDAP | — | ошибки входа и недоступность каталога неразличимы: одна формулировка `errors.auth.credentials_or_directory` |
| Отключение | токен остаётся в хранилище, если его сохраняли | `user.logout` |

Секрет вводится в поле с маскированием, уходит в процесс Rust одним запросом и очищается из поля после отправки (D-09). Он не попадает в YAML, ZIP, URL, журналы, диагностику, буфер обмена и тексты ошибок. «Забыть токен» удаляет запись из системного хранилища, но не отзывает токен на сервере — интерфейс так и пишет. «Завершить сессию» (O-032) стирает секреты из памяти.

## P1-02C1 — вход при подключении (P1-11, 25.10.2026)

Профиль со способом «Имя пользователя и пароль» при «Подключиться» открывает диалог входа на общем компоненте диалога (P1-00D), без отдельного макета:

- заголовок «Вход в «{profile}»», нормализованный адрес моноширинным шрифтом, имя пользователя из профиля (можно изменить только в редакторе профиля);
- поле «Пароль» с маскированием, фокус сразу в нём; «Войти» и «Отмена»; «Сохранить пароль» отсутствует (пароль не сохраняется никогда, P1-02C);
- во время входа — «Вход…» с возможностью отмены; поле пароля очищается после отправки;
- ошибка входа — под полем пароля по коду P1-02D шага 3; для учётной записи с MFA — подсказка про API-токен (`connection.auth.mfa_token_required`); после пяти ошибок — «Zabbix временно заблокировал вход на 30 секунд», кнопка «Войти» недоступна с обратным отсчётом;
- для LDAP — одна формулировка `errors.auth.credentials_or_directory` и индикатор ожидания при долгом ответе;
- профиль с API-токеном из системного хранилища подключается без диалога; без сохранённого токена — тот же диалог с полем «API-токен».

## P1-02D — проверка подключения

Пять шагов строго по порядку. Следующий не начинается, пока не пройден предыдущий; непроверенные шаги показываются как «Не проверялось» с причиной.

| Шаг | Что проверяется | Коды ошибок (P1-00F §3) | Что предложить |
|---|---|---|---|
| 1. Адрес и TLS | имя, соединение, сертификат | `dns_unresolvable`, `connection_refused`, `host_unreachable_or_timeout`, `tls_untrusted`, `tls_certificate_time_invalid`, имя в сертификате не совпадает | исправить адрес; добавить доверенный сертификат УЦ; повторить |
| 2. API Zabbix | `apiinfo.version` без входа | `wrong_base_path`, `redirect`, `not_jsonrpc`, неподдерживаемая версия | исправить базовый путь; «версия {version} поддерживается только для чтения» или отказ |
| 3. Вход | токен или имя и пароль | `auth_failed`, `token_not_authorized`, `token_expired`, `mfa_session_terminated`, нет прав на API | изменить данные входа; использовать API-токен; повторить (после 5 ошибок Zabbix блокирует вход на 30 с) |
| 4. Идентичность сервера | совпадает ли сервер с тем, что сохранён в профиле и в рабочих копиях | сервер изменился | подтвердить новый сервер с последствиями P1-02G |
| 5. Права и возможности | read-методы allowlist, видимость, capability profile адаптера | нет прав на нужные методы | показать, что будет недоступно; продолжить в «Только чтение» |

Тексты ошибок ОС не показываются: классификация по коду (P1-IN-01). Панель «Технические сведения» содержит код, шаг, способ входа и время; «Копировать отчёт» копирует то же, а адрес сервера — только по галке «Включить адрес сервера в отчёт» (по умолчанию выключено). Пароля, токена, ответов сервера и путей к файлам в отчёте нет.

## P1-02E — режим доступа

- После подключения режим всегда «Только чтение» (P1-01C §4). Метка в шапке: «Только чтение · {профиль}».
- «Разрешить запись панелей» открывает подтверждение (макет 05-04): что станет доступно (только операции с глобальными панелями после предпросмотра и подтверждения плана), что не изменяется никогда (узлы сети, шаблоны, элементы данных, триггеры, пользователи), срок действия (до отключения или перезапуска), напоминание, что права учётной записи в Zabbix не расширяются.
- Возврат в «Только чтение» — сразу, без подтверждения; все планы публикации этого подключения становятся недействительными.
- Режим выбирается независимо от серверных прав (O-013): даже Super admin начинает с «Только чтение», а в нём нет пути записи.

| Действие | Только чтение | Чтение-запись |
|---|---|---|
| Просмотр и импорт панелей и шаблонов, проверка источника, подбор узлов сети | да | да |
| Предпросмотр публикации | показывает требования | да |
| Создание, копия, клонирование, добавление страниц и виджетов, замена узла сети | нет | только через проверенный план |
| Изменение узлов сети, шаблонов, элементов данных, триггеров, пользователей | нет | нет |
| Владелец и общий доступ панели | только просмотр | по O-031 |

## P1-02F — TLS и доверенный сертификат УЦ

Выбор: «Системное хранилище сертификатов» (по умолчанию) или «Добавить доверенный сертификат УЦ» — файл PEM только для этого подключения, выбирается нативным диалогом (O-023). Отключить проверку сертификата нельзя: такого переключателя нет ни здесь, ни в настройках.

Сведения о сертификате без чувствительных данных: кому выдан, кем, срок действия, отпечаток SHA-256. Ошибки: «не является доверенным», «недействителен по сроку» (истёк и ещё не действителен на Windows не различаются — одна формулировка), «выдан для другого имени» (ожидаемое и предъявленное имя, где transport их даёт). Смена доверенного сертификата требует повторной проверки шагов 1–5. Обзор всех доверенных сертификатов — в «Настройки → Подключения и сертификаты» (P1-09F).

## P1-02G — переподключение и смена контекста

| Событие | Локальная работа | Что требуется | План публикации |
|---|---|---|---|
| Истекли сессия или токен | доступна | повторный вход | недействителен |
| Временная потеря сети | доступна | «Повторить» | недействителен |
| Ручное «Отключиться» | доступна | — | недействителен |
| Смена адреса в профиле | доступна | проверка, повторная проверка привязок и источников | недействителен |
| Сервер обновлён (другая версия) | доступна | проверка; если версия не поддерживается — только чтение или отказ | недействителен |
| Другая идентичность сервера по тому же адресу | доступна | явное подтверждение нового сервера | недействителен |
| Изменились права учётной записи | доступна | повторная проверка шага 5 | недействителен |
| Переключение на другой профиль | доступна | подключение другого профиля | недействителен для прежнего |

Ни одно событие не удаляет черновики, рабочие копии и снимки. Незавершённая операция журнала показывается до новых записей (P1-01C §6).

## P1-02H — handoff для P2-01

Данные профиля для интерфейса (без секретов): `local_id`, `name`, `endpoint_display`, `api_url_display`, `auth_method` (`api_token`/`password`), `secret_storage` (`none`/`os_store`), `username` (для пароля), `trust` (`system`/`custom_ca` + сведения о сертификате), `last_check` (`at`, `server_version`, `result_code`), `state` (P1-01C ось D), `mode`.

| Команда | Предусловия | Успех | Ошибки (коды) |
|---|---|---|---|
| `profile.create`, `profile.update` | валидный адрес; для `http` с сохранённым токеном — подтверждение | профиль сохранён; при смене сервера — событие `connection.context_changed` | ошибки адреса |
| `profile.duplicate`, `profile.delete` | профиль не подключён или отключается сначала | — | — |
| `connection.test` | профиль; секрет передаётся одним запросом | события `test.step` по пяти шагам | коды P1-02D |
| `connection.connect` / `disconnect` | — | `connection.state_changed` | коды P1-02D |
| `connection.enable_writes` | `connected`, подтверждение пользователя | режим `read_write` | — |
| `connection.set_read_only` | — | режим `read_only`, планы недействительны | — |
| `credential.forget` | — | запись удалена из системного хранилища | ошибка хранилища |

Ответы API приложения содержат только коды и параметры, а не готовый текст. Фокус: после ошибки шага фокус переходит на первое действие исправления; результат проверки объявляется live-region; форма не теряет введённое при ошибке (кроме поля секрета после отправки).

## Проверки приёмки P1-02

- Адрес с портом и базовым путём вводится без обходов, адрес API виден до сохранения.
- Токен и имя с паролем разведены; пароль не сохраняется; токен сохраняется только по выбору.
- Автономная работа доступна без профиля.
- Текущие адрес, версия и режим видны; «Только чтение» не ведёт к записи.
- Ни в одном состоянии, отчёте и тексте ошибки нет секрета.
- Проверку TLS нельзя отключить.
