# ZDashstitch v0.6 — матрица обработки замечаний критического аудита v0.5

**Коды:** `CLOSED-SPEC` — закрыт контрактом/документом и примером; `CLOSED-TEST` — реализован и подтверждён Python-эталоном; `RUST-TEST` — эквивалентное правило реализовано и локально проверено в Rust; `P0-LIVE` — требуется лабораторный Zabbix 7.4; `RUST-TODO` — проверенное проектное правило ещё предстоит реализовать в Rust. Успешная запись в живой Zabbix подтверждена только там, где это явно указано как P0 на 7.4.16; остальные строки такого подтверждения не дают.

## Воспроизведённые A1—A4

| ID | Изменение | Текущее подтверждение |
|---|---|---|
| A1 | Нефоллов открытие каждого компонента POSIX-пути + запрет symlink, ZIP без распаковки; отдельный запрет Windows reparse point для Rust | CLOSED-TEST / RUST-TEST, включая Windows handle-relative no-follow |
| A2 | Глобальная уникальность `slot_id`, ссылки overrides на реальные слоты | CLOSED-TEST / RUST-TEST |
| A3 | Для `manual` не требуем версию, `export_format_version` отдельно от `source_server_version`, поддержка legacy | CLOSED-TEST / RUST-TEST |
| A4 | `binary` в каталоге; несовместимые MVP-виджеты блокируют использование | CLOSED-TEST / RUST-TEST |

## Принципиально остаётся за пределами документационной проверки

- Реальный импорт экспортов шаблонов YAML/JSON/XML 7.4: необходимы fixture и парсеры.
- Прямое и косвенное обнаружение зависимостей действующих виджетов, `graphid`/`itemid`, ссылки между виджетами, `dashboard.get/create/update` и `widgetid`: P0-LIVE.
- Невозможность гарантированного отката удалённых источников, гонки между последним чтением и записью: ограничения самого API и среды.
- Политика патчей адаптера и `VerifiedPlan`: узкая реализация испытана на 7.4.16; другие патчи и операции остаются закрыты до отдельных контрактов.
- Защита браузерного сеанса и GUI-хранилище пароля/токена остаются TODO; файловые Windows reparse points уже отклоняются Rust no-follow слоем.
- Тесты 6.x, 7.0 LTS, 8.0, 5.x — после MVP; модель заранее имеет registry и версионируемые адаптеры.
