## Зачем нужен проект

При эксплуатации Zabbix однотипные операции отнимают много времени. Например, нужно собрать панели Mamonsu/PostgreSQL и ClickHouse для Prod и Pilot, разместить на странице ClickHouse показатели Keeper, HAProxy и Linux, заменить выведенный из эксплуатации хост сразу во многих виджетах, либо перенести готовую компоновку в закрытый контур.

ZDashstitch — **бесплатный локальный инструмент с открытым кодом**, ориентированный на удобную работу с **существующими стандартными и произвольными пользовательскими шаблонами Zabbix**. Мы не заменяем мониторинг, не управляем сбором метрик и не стремимся реализовать весь Grafana в MVP.

## Планируемый MVP 0.1.0

- Работать **без подключения к Zabbix**: импортировать экспорты шаблонов 7.4 в YAML/JSON/XML, составлять каталог метрик, проектировать панели и страницы, использовать на одной странице/в одном графике данные из нескольких шаблонов.
- Создавать offline типизированный проект целой панели либо отдельной страницы, сохранять DATA-ONLY пакет без привязки к конкретным корпоративным узлам сети и позднее назначать реальные источники и явную цель в закрытом контуре. `project/v2` хранит ровно один typed root; `project/v1` остаётся читаемым legacy multi-dashboard container и мигрируется только с явным выбором.
- Подключаться к Zabbix **7.4** по API-токену или логину/паролю, если авторизация разрешена политиками сервера и MFA.
- Создавать глобальные панели с несколькими страницами, сохранять копию панели с сервера новой панелью, обновлять существующую панель, добавлять страницы и виджеты в существующие (полный перечень операций — ADR-006), формировать Graph (`svggraph`) с несколькими рядами и отдельные числовые Item value (`item`).
- Применять базовые профили оформления и одиночные заготовки виджетов `svggraph` и `item` (O-012, вариант Б): профиль копирует значения полей в виджет; заготовка — один виджет без положения с параметрами «роль узлов» и «метрика», источники которых привязываются явно; оба экспортируются отдельными файлами из библиотеки, не в пакете черновика.
- Копировать глобальные панели между зонами/группами узлов внутри одного подключения Zabbix с явным сопоставлением источников; массово заменять хосты в проверенных типах виджетов.
- Показывать все изменения и несовпадения **до записи**, сохранять незатронутые данные, фиксировать результат и запрещать неподтверждённые операции.
- Брать весь пользовательский текст Rust/TypeScript/Svelte из data-only каталогов: английский — исходный язык, русский — полный перевод MVP; поддерживать `system`, светлую, тёмную и высококонтрастную темы на семантических design tokens.

**Платформы:** Windows 10+ и Linux с GUI (окно программы на WebKitGTK 4.1, иначе браузер). Сборки и поддержка macOS отложены до post-MVP этапа с несколькими версиями Zabbix. **Стек:** Rust + Axum (локальный HTTP на `127.0.0.1`) + Svelte/TypeScript, собственное окно программы на системном веб-движке (WebView2 / WebKitGTK 4.1), запасной вариант — браузер (O-036); пользовательские CLI/TUI и обязательная серверная установка не нужны.

### Шлюзы качества

| Шлюз | Необходимое доказательство |
|---|---|
| G0 | Rust-фундамент, контракты чтения/записи на явно разрешённом тестовом Zabbix 7.4 и закрытый publisher через `VerifiedPlan` |
| G1 | Поэтапно: G1a — согласованные макеты, состояния, локализуемые тексты и handoff для подключений, импорта, ReplaceHost, Clone и публикации; G1b — для остальных MVP-потоков |
| G2 | ReplaceHost сохраняет посторонние данные виджетов и безопасно отклоняет неподдержанные ссылки |
| G3 | CloneDashboard создаёт проверенную копию, не изменяя оригинал |
| G4 | Проект Dashboard или Page создаётся и переносится без Zabbix и внешнего интернета; формат typed root определён и мигрирует legacy v1 без тихой потери |
| G5 | Dashboard project создаёт новый дашборд, Page project добавляет страницу в явно выбранный дашборд, а существующее содержимое не повреждается |
| G6 | Сквозная приёмка GUI на Windows/Linux, матрица поддержки и известные ограничения |

Успешная проверка схемы не закрывает ни один шлюз записи в Zabbix.

### Не входит в MVP

Адаптеры Zabbix 7.0/6.0/8.0/5.x, template dashboards, автоматическая двусторонняя синхронизация, каталог сообщества, встроенный ИИ/MCP, произвольный CSS/JS/PHP, серверные Custom Widgets, общий многопользовательский сервис и пользовательский CLI/TUI. Всё это рассматривается только в [дорожной карте после MVP](ROADMAP.ru.md).

## Пример: глобальная панель DB Pilot

Одна глобальная панель содержит страницы «PostgreSQL», «ClickHouse», «ОС» и «Backup». Страница ClickHouse может объединять метрики ClickHouse, Keeper, HAProxy, Linux; один график может объединять несколько хостов, а для каждого выбранного хоста можно создать отдельную числовую карточку.

Связывание метрик с `hostid`/`itemid` выполняется **в целевом Zabbix**, а не при внешнем проектировании. [`examples/dashboard-v2.yaml`](examples/dashboard-v2.yaml) и [`examples/page-v2.yaml`](examples/page-v2.yaml) показывают оба typed root; [`examples/db-pilot.yaml`](examples/db-pilot.yaml) остаётся примером legacy `project/v1`.

## Безопасность и автономность

Переносимый файл **не означает автоматически обезличенный файл**: названия, ключи и описания показателей могут содержать внутренние сведения. Реальные адреса и ID хостов, пароли, токены, снимки панелей и состояние публикаций отделены от переносимого пакета; их нельзя автоматически экспортировать. Для внешнего ИИ допускаются только сведения, разрешённые правилами организации.

Запись разрешается через единый механизм проверки и подтверждения. Первые испытания проводятся на тестовом Zabbix 7.4; прохождение тестов формата не является доказательством безопасной публикации.

Полная постановка проблемы и критерии успеха: [цели проекта](docs/product/PROJECT_GOALS.md) и [сквозные сценарии](docs/product/USE_CASES.md).

## Направление реализации

- Rust 1.94.1 / edition 2024 workspace: `core`, `template_import`, `zabbix`, `application`, `apps/local_server`.
- Axum уже предоставляет read-only health endpoint и собранный UI только через loopback; session, Origin/Host, CSRF и DNS rebinding обязательны до появления изменяющих маршрутов.
- Svelte/TypeScript отвечает за GUI и никогда не обращается к Zabbix напрямую.

P0-01 реализует только запускаемый каркас и не является редактором панелей. Все направления после MVP сведены в двуязычную [дорожную карту](ROADMAP.ru.md). Команды сборки и локального запуска находятся в [`DEVELOPMENT.md`](DEVELOPMENT.md).

## Зачем пока нужен Python

Python — **временная исполняемая спецификация**, а не будущая runtime-зависимость продукта. Сейчас он детерминированно генерирует пять JSON Schema, проверяет переносимый YAML/data-only ZIP и межфайловые инварианты, а также предоставляет положительные и отрицательные фикстуры, поведение которых обязан повторить Rust.

P0-02 и P0-03 уже дали эквивалентные Rust-модели, семантические валидаторы и безопасный файловый/DATA-ONLY ZIP слой. Python теперь нужен только разработчикам как единственный генератор схем и независимый регрессионный эталон; в обычный продуктовый процесс и поставку GUI он не входит.

## Для разработчиков и агентов

Сначала прочитать [`AGENTS.md`](AGENTS.md), [карту документации](docs/README.ru.md), нормативные ADR и схемы. Текущий рабочий список ведётся локально в игнорируемом `TASKS_RU.md`. Прежние редакции доступны в истории Git; локальный игнорируемый архив, если он есть, не является нормативным.

Проверка существующих форматов (Python 3.11+; версии зависимостей закреплены в `requirements-reference.txt`):

```bash
python -m pip install -r requirements-reference.txt
python tools/build_schemas.py
python tools/validate.py examples/db-pilot.yaml
python tools/validate.py --package examples/db-pilot-package.zip
python -m pytest -q
```

Это тесты эталонных правил, а не готового продукта. Rust `core` повторяет legacy-форматы v1, typed `project/v2`, явную миграцию выбранного v1 root и безопасный DATA-ONLY ZIP round-trip. Transport и закрытый publisher проверены на лабораторной Zabbix 7.4.16. Пользовательского GUI-сценария публикации ещё нет, HTTP-запись отключена.

## Доступность

Интерфейс рассчитан на работу только с клавиатуры, масштаб 200 % и 400 %, светлую, тёмную и высококонтрастную темы и режим контрастности операционной системы; клавиатура и масштаб проверены вручную на Windows. Поддержка экранных дикторов заложена в разметке (ориентиры, доступные имена, объявления ошибок и хода работы), но **с экранным диктором не проверялась**. Для проверки рекомендуются NVDA в Windows и Orca в Linux. Будем рады замечаниям и pull request от пользователей экранных дикторов.

## Участие в проекте

Принимаются отдельные pull request с переводами, а также синтетические фикстуры, документация и проверяемые тесты совместимости. Изменения Rust/TypeScript/Svelte и build scripts нельзя смешивать с переводческим pull request. Новый язык может сначала иметь статус experimental и использовать английский fallback; структурные проверки и безопасность при этом не ослабляются. Правила описаны в [CONTRIBUTING.md](CONTRIBUTING.md) и [контракте UI/локализации/тем](docs/architecture/ui_i18n_theme_contract_v1_ru.md).
