# Синтетические эталоны файлового импорта Zabbix 8.0

YAML, JSON и XML описывают два вымышленных шаблона. У одного есть обычный элемент с типом по умолчанию, JSON-элемент и LLD-прототип JSON-элемента. У второго есть текстовый элемент с тем же ключом, что у JSON-элемента первого шаблона. Используются вымышленные имена, ключи и UUID.

- Строковый маркер версии `8.0`, структура шаблона, зависимости, `UNSIGNED` по умолчанию и `JSON (6)` для элементов и прототипов сверены со [спецификацией экспорта шаблонов 8.0](https://www.zabbix.com/documentation/8.0/en/manual/config/xml_export_import/templates).
- Обёртки форматов сверены с [руководством по экспорту конфигурации 8.0](https://www.zabbix.com/documentation/8.0/en/manual/config/xml_export_import) и [примером ответа configuration.export для XML](https://www.zabbix.com/documentation/8.0/en/manual/api/reference/configuration/export).

Эталоны проверяют локальную нормализацию по опубликованному формату. Для проверки точного выпуска 8.0 нужны реальные разрешённые выгрузки.

Парсер хранит ключ, UUID правила LLD и ссылки на прототипы элементов. Связь между вложенными правилами (`parent_discovery_rule`) и прочие поля вне читаемого подмножества отмечаются общей диагностикой `source_partial`. Значения элементов и экземпляры LLD появляются только в отдельных серверных сценариях.
